정수계획 모델링 ①: 0과 1로 논리 적기

"창고를 연다, 안 연다", "이 일을 하면 저 일도 해야 한다", "둘 중 하나만 고른다." 이런 말은 수식처럼 보이지 않습니다. 그런데 0 아니면 1만 되는 변수를 쓰면 이런 말을 모두 1차 부등식으로 적을 수 있습니다. 이 장은 그 요령과, 적은 식이 정말 그 뜻인지 확인하는 방법을 배웁니다.

  • 미리 알아야 할 것. 2장(결정변수, 제약, 목적함수, LP·IP·MIP라는 이름), 6장(가능 영역, 꼭짓점, 정수점만 모으면 볼록이 아니라는 것). 고등학교의 「집합과 명제」(p → q, 대우, 진리집합).
  • 이 장을 읽고 나면. "a이면 b 또는 c" 같은 말을 부등식으로 바꾸고, 진리표로 검산할 수 있습니다. big-M이 무엇이고 왜 M을 가장 작게 골라야 하는지 설명할 수 있습니다.

식을 적는 요령만 다룹니다. 그렇게 적은 문제를 솔버가 어떻게 푸는지는 13장, 같은 뜻의 여러 식 가운데 어느 것이 더 좋은지는 14장에서 봅니다.

1부 · 정수 조건이 더해진 LP

「한다, 안 한다」를 수로: 이진변수

방의 전등 스위치는 꺼짐과 켜짐 두 상태뿐입니다. 꺼짐을 0, 켜짐을 1이라고 적으면 스위치 하나의 상태가 수 하나가 됩니다. 최적화에서도 "한다, 안 한다"를 이렇게 적습니다.

정의 값이 0 또는 1뿐인 변수를 이진변수(binary variable)라고 하고 x ∈ {0, 1}로 적습니다. LP에 "모든 변수는 정수"라는 조건을 더한 문제가 정수계획(IP)이고, 변수 가운데 일부만 정수여야 하는 문제가 혼합정수계획(MIP)입니다. 목적함수와 제약은 여전히 1차식이어야 합니다.

2장에서 이름만 봤던 것을 다시 정의했습니다. 이진변수는 "0 이상 1 이하인 정수 변수"이므로 정수 변수의 특별한 경우입니다. 트럭 예는 x, y가 모두 정수인 IP였습니다. 창고를 열지 말지(이진)와 창고에서 보내는 양(실수)을 함께 정하는 문제는 MIP입니다.

"x는 정수"라는 한 줄을 더하는 것은 작은 변화처럼 보입니다. 하지만 문제의 성격이 완전히 달라집니다.

컴퓨터 과학에서는 이런 문제를 NP-hard라고 부릅니다. "문제가 커져도 빠르게 푸는 방법이 아직 알려지지 않았고, 아마 없을 것이라고 믿어지는 문제 무리"라는 뜻으로만 알아 두면 됩니다. 정수계획은 일반적으로 NP-hard입니다.

이렇게 어려운데도 정수계획을 쓰는 이유가 둘 있습니다. 첫째는 표현력입니다. 이 장과 다음 장에서 보듯이 이진변수와 1차 부등식만으로 현실의 거의 모든 조건을 적을 수 있습니다. 둘째는 LP를 발판으로 쓸 수 있다는 점입니다. 정수 조건만 지우면 쉬운 LP가 되고, 그 LP의 답이 "진짜 답은 이보다 좋을 수 없다"는 한계를 알려 줍니다. 솔버는 이 한계를 이용해 2n개의 후보 대부분을 보지 않고 건너뜁니다. 그 원리가 13장입니다.

맞게 적는다는 것: 두 방향

모형을 적는 일은 "내가 허용하고 싶은 답들"과 "식을 만족하는 정수점들"을 정확히 같게 만드는 일입니다. 어긋나는 방향이 둘 있습니다.

이진변수 a, b, c로 "셋 중 많아야 하나만 한다"를 적는다고 합시다. 맞는 식은 a + b + c ≤ 1입니다.

적은 식무슨 일이 생기나잘못의 종류
a + b + c ≤ 2(1, 1, 0)이 통과한다. 둘을 하는 답인데 막지 못한다엉터리 답을 들였다
a + b + c ≤ 0(1, 0, 0)이 잘린다. 하나만 하는 멀쩡한 답인데 막았다멀쩡한 답을 잘라 냈다
a + b + c ≤ 1하나 이하인 네 가지만 통과한다맞게 적었다
핵심 사실 식을 맞게 적었다는 것은 두 가지를 모두 뜻합니다. ① 엉터리 답을 들이지 않는다. 식을 만족하는 정수점은 모두 실제로 허용되는 답이다. ② 멀쩡한 답을 잘라 내지 않는다. 실제로 허용되는 답은 모두 식을 만족한다.

고등학교의 말로 하면 "식을 만족한다"와 "허용되는 답이다"가 서로 필요충분조건이어야 합니다. 한쪽만 확인하고 넘어가면 사고가 납니다. 이 장의 확인은 모두 이 두 방향을 따집니다.

대학 교재에서는 ①을 건전성(soundness), ②를 완전성(completeness)이라고 부릅니다.

2부 · 논리를 부등식으로

명제에서 부등식으로

조건 p, q에 대해 명제 p → q("p이면 q")가 참이라는 것은, p의 진리집합 P가 q의 진리집합 Q에 포함된다(P ⊂ Q)는 뜻이었습니다. p → q가 거짓이 되는 것은 "p는 참인데 q는 거짓"인 경우가 있을 때뿐입니다. 그리고 p → q와 그 대우 ~q → ~p는 참, 거짓이 같습니다.

이진변수 a를 "a를 한다"는 조건으로 읽습니다. a = 1이면 참, a = 0이면 거짓입니다. 그러면 "a를 하면 b도 해야 한다"는 a → b이고, 이 말이 깨지는 경우는 "a는 하는데(a = 1) b는 안 하는(b = 0)" 하나뿐입니다. 네 가지 경우 (a, b) = (0, 0), (0, 1), (1, 0), (1, 1) 가운데 (1, 0)만 막으면 됩니다.

부등식 a ≤ b가 정확히 그 일을 합니다. 6장에서 배운 부등식의 영역으로 그려 보면 한눈에 보입니다.

이처럼 이진변수 몇 개에 대한 부등식은 "0과 1의 조합 가운데 어느 것을 막는가"로 읽습니다. 그 읽는 법을 표로 만든 것이 진리표입니다.

진리표로 확인하기

이진변수가 k개면 0과 1의 조합은 2k가지입니다. 이것을 한 줄에 하나씩 모두 적고, 줄마다 "말이 참인가"와 "부등식이 성립하는가"를 나란히 적은 표를 진리표라고 합니다. 두 열이 모든 줄에서 같으면, 그 부등식은 그 말과 정확히 같은 뜻입니다. 앞 절의 두 방향(엉터리 답을 들이지 않는다, 멀쩡한 답을 자르지 않는다)이 한꺼번에 확인됩니다.

예로 "a를 하면 b나 c 가운데 적어도 하나는 해야 한다"와 부등식 a ≤ b + c를 비교합니다. 이 말이 거짓인 경우는 a = 1인데 b = c = 0일 때뿐입니다.

여덟 줄 모두에서 두 열이 같습니다. a = 0인 네 줄에서 말이 「참」인 것이 낯설 수 있습니다. "비가 오면 우산을 가져간다"는 약속은 비가 오지 않은 날에는 어길 수가 없습니다. a를 하지 않았으면 "a를 하면 …"이라는 약속은 깨지지 않은 것입니다.

줄이 많아지면 컴퓨터에게 시키면 됩니다. 2장의 전수 탐색과 같은 생각입니다.

for a in range(0, 2):

            if logic != ineq:
                ok = False
print(ok)

「또는」 묶음 하나 = 부등식 하나

진리표는 확인하는 도구입니다. 식을 만드는 데는 규칙 하나면 충분합니다. 먼저 "a이면 b"를 다르게 말해 봅니다. 이 말이 깨지는 경우는 a = 1, b = 0뿐이었으므로, 깨지지 않는 경우는 "a = 0이거나 b = 1"입니다.

"a이면 b"  =  "a를 안 하거나, b를 한다"

이렇게 조건들을 「또는」으로 이은 묶음으로 바꾸고 나면, 부등식은 기계적으로 나옵니다.

핵심 사실 이진변수에 대해 "x1, x2, … 가운데 하나 이상을 하거나, w1, w2, … 가운데 하나 이상을 안 한다"는 말은 다음 부등식과 같은 뜻입니다.
(x1 + x2 + …) + (1 − w1) + (1 − w2) + … ≥ 1

x는 "한다"일 때 1이 되고, 1 − w는 "안 한다"(w = 0)일 때 1이 됩니다. 그래서 왼쪽은 「또는」으로 이은 조건들 가운데 참인 것의 개수입니다. 「또는」 묶음이 참이라는 것은 참인 조건이 하나 이상이라는 것이고, 그것이 바로 "왼쪽 ≥ 1"입니다.

자주 쓰는 말을 이 규칙으로 만들어 봅니다. 가운데 열에서 "~을 안 하거나"는 1 − (변수)로, "~을 하거나"는 변수 그대로 옮깁니다.

하고 싶은 말「또는」 묶음으로규칙을 적용하면정리하면
a이면 ba를 안 하거나 b를 한다(1 − a) + b ≥ 1a ≤ b
a와 b를 둘 다 할 수는 없다a를 안 하거나 b를 안 한다(1 − a) + (1 − b) ≥ 1a + b ≤ 1
a이면 b 또는 ca를 안 하거나 b를 하거나 c를 한다(1 − a) + b + c ≥ 1a ≤ b + c
a와 b를 다 하면 c도 한다a를 안 하거나 b를 안 하거나 c를 한다(1 − a) + (1 − b) + c ≥ 1c ≥ a + b − 1
셋 중 적어도 하나는 한다a를 하거나 b를 하거나 c를 한다a + b + c ≥ 1a + b + c ≥ 1
셋 중 많아야 하나만 한다두 개씩 짝마다 "둘 다는 못 한다"세 줄a + b ≤ 1,  a + c ≤ 1,  b + c ≤ 1

넷째 줄을 직접 확인해 봅니다. a = b = 1이면 식은 c ≥ 1이 되어 c = 1을 강제합니다. a나 b 가운데 하나라도 0이면 식은 c ≥ 0 또는 c ≥ −1이 되어 아무것도 요구하지 않습니다. 말 그대로입니다.

말이 복잡해도 방법은 같습니다. 「또는」 묶음 여러 개를 "그리고"로 이으면 되고, "그리고"는 부등식을 여러 줄 적는 것입니다. 예를 들어 "a를 하면 b와 c 가운데 하나는 해야 하고, d는 하면 안 된다"는 "a이면 b 또는 c" 그리고 "a와 d를 둘 다 할 수는 없다"이므로 a ≤ b + c와 a + d ≤ 1 두 줄입니다.

논리학에서는 「또는」을 ∨, 「그리고」를 ∧, 「아니다」를 ¬로 적습니다. 모든 논리식은 「또는」 묶음 여러 개를 「그리고」로 이은 꼴로 바꿀 수 있다는 것이 알려져 있습니다(논리곱 표준형). 그래서 이진변수에 대한 어떤 논리 조건도 1차 부등식 몇 줄로 적을 수 있습니다.

같은 뜻, 다른 식

표의 마지막 줄 "셋 중 많아야 하나"는 규칙대로 하면 세 줄이 나왔습니다. 그런데 1부에서는 같은 말을 한 줄 a + b + c ≤ 1로 적었습니다. 어느 쪽이 맞을까요?

둘 다 맞습니다. 여덟 가지 0/1 조합을 넣어 보면 두 식이 통과시키는 조합이 똑같습니다(둘 이상이 1이면 어느 쪽이든 위반). 같은 정수해 집합을 적는 방법은 하나가 아닙니다.

하지만 정수 조건을 지우고 0과 1 사이의 소수까지 허용하면 두 식은 달라집니다. 점 (a, b, c) = (1/2, 1/2, 1/2)을 넣어 봅니다.

식(1/2, 1/2, 1/2)을 넣으면결과
세 줄: a + b ≤ 1, a + c ≤ 1, b + c ≤ 11/2 + 1/2 = 1 ≤ 1 (세 줄 모두)통과
한 줄: a + b + c ≤ 13/2 ≤ 1위반

"세 가지를 반씩 한다"는 엉터리 점을 한 줄짜리 식은 막고, 세 줄짜리 식은 막지 못합니다. 정수해만 보면 차이가 없는데 왜 이것이 중요할까요? 솔버가 정수 조건을 지운 LP를 먼저 풀어서 한계를 얻기 때문입니다. 그 LP에 엉터리 소수 점이 적게 섞일수록 한계가 정확해집니다. 이 이야기는 14장의 주제이고, 지금은 "뜻이 같아도 식에 따라 좋고 나쁨이 있다"만 기억하면 됩니다.

한 방향과 양방향

a ≤ b는 "a이면 b"일 뿐입니다. 거꾸로 "b이면 a"까지 말하지는 않습니다. b = 1, a = 0도 통과합니다. 고등학교에서 p → q가 참이어도 q → p는 따로 따져야 했던 것과 같습니다.

"a를 하는 것과 b를 하는 것이 필요충분"이라면 반대 방향 b ≤ a도 함께 적어야 하고, 둘을 합치면 a = b입니다. 조금 더 복잡한 양방향 정의도 같은 방식으로 만듭니다.

정의하고 싶은 것식각 줄이 하는 일
a = "b나 c 가운데 하나라도 하면 1"a ≥ b,  a ≥ c,  a ≤ b + c앞의 두 줄: b나 c가 1이면 a = 1. 셋째 줄: 둘 다 0이면 a = 0
a = "b와 c를 둘 다 하면 1"a ≤ b,  a ≤ c,  a ≥ b + c − 1앞의 두 줄: 하나라도 0이면 a = 0. 셋째 줄: 둘 다 1이면 a = 1

두 표 모두 여덟 줄짜리 진리표로 확인했습니다. 실제 모형에서는 양방향을 다 적지 않고 한 방향만 적는 경우가 많습니다. 반대 방향이 저절로 성립하는 경우가 있기 때문입니다. 다음 절이 그 이야기입니다.

쓸모없는 스위치는 꺼진다

2장의 창고 예를 봅니다. y는 "창고를 연다", xi는 "고객 i에게 이 창고에서 보낸다"이고, 창고를 열면 고정비 100이 듭니다.

최소화  100y + (그 밖의 비용)창고 여는 값
제약    xi ≤ y모든 고객 i = 1, …, 10

제약은 "보내려면 열어야 한다"(xi이면 y)는 한 방향뿐입니다. 반대 방향, 곧 "아무에게도 안 보내면 열지 않는다"는 적지 않았습니다. 그러면 x가 모두 0인데 y = 1인 답, 곧 쓰지도 않을 창고를 여는 답도 제약은 통과합니다. 괜찮을까요?

핵심 사실 최소화 문제에서 이진변수 y의 비용이 0보다 크고, y가 제약에서 "xi ≤ y" 꼴로만 나타난다고 합시다. 그러면 최적해에서는 xi가 모두 0일 때 반드시 y = 0입니다.

최적해라고 주장하는 답에서 x가 모두 0인데 y = 1이라고 해 봅시다. y만 0으로 바꿔 봅니다. 제약 xi ≤ y는 0 ≤ 0이 되어 여전히 성립하고, 다른 제약에는 y가 없으니 영향이 없습니다. 그런데 비용은 100만큼 줄었습니다. 더 좋은 가능해가 있으니 처음 답은 최적해가 아닙니다.

제약이 막지 않아도 목적함수가 알아서 쓸모없는 스위치를 끕니다. 그래서 한 방향만 적어도 됩니다. 식이 줄어드는 만큼 모형이 가벼워집니다.

이 논리는 스위치의 비용이 0보다 클 때만 통합니다. 비용이 0이면 y를 켜 둔 답과 끈 답이 똑같이 좋아서, 최적해에 "쓸데없이 켜진 스위치"가 섞일 수 있습니다. 그것이 해로운지는 따로 따져야 합니다. 다음 장에서 볼 tryAgain 모형의 y가 바로 비용이 0인 스위치입니다.

3부 · 스위치로 제약을 켜고 끄기

big-M: 스위치로 제약을 켜고 끄기

지금까지는 이진변수끼리의 관계였습니다. 이번에는 이진변수가 다른 제약 하나를 통째로 켜고 끄게 만들어 봅니다. Python이라면 if 한 줄이면 되는 일입니다.

창고가 하루에 보내는 양을 w(톤)라고 합시다. 창고의 용량 때문에 0 ≤ w ≤ 40입니다. 여기에 "야간에 운영하면(x = 1) 소음 때문에 10톤까지만 보낼 수 있다"는 조건을 더하고 싶습니다.

x = 1이면  w ≤ 10,    x = 0이면  조건 없음(w ≤ 40 그대로)

모형에는 if를 쓸 수 없습니다. 1차식만 쓸 수 있으니까요. 그래서 요령을 씁니다. 스위치가 꺼졌을 때 오른쪽이 넉넉하게 커지도록 식을 고칩니다.

w ≤ 10 + 30(1 − x)
  • x = 1을 넣으면 w ≤ 10. 원하던 조건이 켜집니다.
  • x = 0을 넣으면 w ≤ 40. 원래 있던 용량 제한과 같아서 아무것도 새로 막지 않습니다. 조건이 꺼진 것입니다.

여기서 30이 big-M이라고 부르는 상수입니다. 보통 글자 M으로 적습니다.

정의 이진변수 x가 1일 때만 "g ≤ 0"이라는 제약을 적용하고 싶을 때, 상수 M을 써서 g ≤ M(1 − x)로 적는 것을 big-M 제약이라고 합니다. x = 1이면 g ≤ 0, x = 0이면 g ≤ M입니다. 다른 제약을 모두 지키는 한 g가 M을 넘을 수 없을 때, 곧 M ≥ (g가 가질 수 있는 최댓값)일 때 M이 유효하다고 합니다.

위 예에서는 g = w − 10이고, w ≤ 40이므로 g의 최댓값은 30입니다. 그래서 M = 30이 유효합니다. M을 다르게 잡으면 어떻게 되는지 봅니다.

가장 작은 M 고르기: 배달 시각의 예

택배 트럭이 고객들을 차례로 도는 문제에서 big-M이 실제로 쓰이는 모습을 봅니다. 시각은 아침 8시부터 센 분(分)으로 적겠습니다.

기호뜻예의 값
xij트럭이 고객 i 다음에 바로 고객 j에게 가면 1 (이진변수)정해야 할 값
ti, tj고객 i, j의 집에서 일을 시작하는 시각 (실수 변수)정해야 할 값
si고객 i의 집에서 일하는 데 걸리는 시간10
τiji에서 j까지 가는 데 걸리는 시간 (τ는 그리스 글자 「타우」)15
[ai, bi]고객 i가 받을 수 있는 시간대. ai ≤ ti ≤ bi. 시간창이라고 부릅니다bi = 50,  aj = 20

i 다음에 j로 간다면, j에서의 시작 시각은 "i에서 시작한 시각 + 일한 시간 + 이동 시간"보다 빠를 수 없습니다. 가지 않는다면 두 시각 사이에 아무 관계가 없습니다.

xij = 1이면  tj ≥ ti + si + τij

big-M으로 적으면 다음과 같습니다.

tj ≥ ti + si + τij − M(1 − xij)

xij = 0일 때 이 식은 tj ≥ ti + si + τij − M입니다. 이것이 어떤 ti, tj에 대해서도 저절로 성립하려면 M이 ti + si + τij − tj의 최댓값 이상이어야 합니다. 이 값이 가장 커지는 것은 ti가 가장 늦고(bi) tj가 가장 이를 때(aj)입니다.

가장 작은 유효한 M = bi + si + τij − aj = 50 + 10 + 15 − 20 = 55

공식에서 두 가지 덤이 나옵니다. 계산한 M이 0 이하이면(bi + si + τij ≤ aj) i를 가장 늦게 떠나도 j의 시간창이 열리기 전에 도착한다는 뜻이므로, 이 제약은 xij와 상관없이 항상 성립합니다. 적지 않아도 됩니다. 반대로 i에서 가장 일찍 떠나도 j의 시간창이 닫힌 뒤에 도착한다면(ai + si + τij > bj) i 다음에 j로 가는 것은 불가능하므로 xij = 0으로 못 박아 변수를 하나 줄일 수 있습니다.

M이 크면 왜 나쁜가

M = 55든 M = 1000이든, x가 0 아니면 1인 한 허용되는 답은 똑같습니다. 차이는 정수 조건을 지운 LP에서 드러납니다. 그 LP에서는 x가 0.9 같은 값도 가질 수 있습니다. "i 다음에 j로 90%만큼 간다"는, 현실에서는 뜻이 없는 값입니다.

xij = 0.9를 넣으면 식은 tj ≥ ti + 25 − 0.1M이 됩니다.

Mx = 0.9일 때의 식읽기
55tj ≥ ti + 19.590% 켜진 스위치에 걸맞게 제약이 대부분 살아 있다
1000tj ≥ ti − 75j가 i보다 75분 먼저여도 된다. 제약이 사실상 꺼졌다

M이 크면 스위치를 10%만 꺼도 제약이 완전히 풀립니다. 그러면 LP는 "거의 간다고 해 놓고 순서 조건은 무시하는" 엉터리 점을 마음껏 쓸 수 있고, 그 LP가 알려 주는 한계는 진짜 답과 동떨어진 값이 됩니다. 앞의 「같은 뜻, 다른 식」에서 본 것과 같은 현상입니다. 솔버가 건너뛸 수 있는 후보가 줄어 풀이가 느려집니다.

그래서 big-M은 필요할 때만, 그리고 가장 작은 M으로 씁니다. 가이드가 1등 풀이의 장점으로 "big-M이 없다"를 꼽는 것도 이 때문입니다.

지시 제약, 고정비, 택일

big-M과 같은 생각으로 적는 관용구 셋을 더 봅니다.

지시 제약

요즘 솔버는 "x = 1이면 g ≤ 0"을 M 없이 그대로 받아 주기도 합니다. 이것을 지시 제약(indicator constraint)이라고 합니다. 솔버가 속에서 알아서 처리하거나 스스로 M을 계산합니다. 허용되는 답의 집합은 유효한 M을 쓴 big-M 제약과 같습니다. 새로운 일을 할 수 있게 되는 것이 아니라, M을 고르는 일을 솔버에게 맡기는 것입니다.

고정비

창고에서 내보내는 양 w(실수, 0 이상)가 0보다 크려면 창고를 열어야(y = 1) 하고, 열면 보내는 양과 상관없이 고정비 100이 든다고 합시다. 보내는 양 1톤마다 운송비 2가 더 듭니다. 비용을 w의 함수로 그리면 w = 0에서 뚝 끊어진 그래프가 됩니다.

식은 w ≤ U·y 한 줄입니다. U는 w가 가질 수 있는 가장 큰 값(여기서는 용량 40)입니다. y = 0이면 w ≤ 0이라 못 보내고, y = 1이면 w ≤ 40이라 용량까지 보낼 수 있습니다. U가 big-M 노릇을 하는 것을 알 수 있습니다. "w = 0이면 y = 0"이라는 반대 방향은 적지 않았지만, 「쓸모없는 스위치는 꺼진다」와 같은 이유로 최적해에서는 저절로 성립합니다.

택일

"조건 A나 조건 B 가운데 적어도 하나는 성립해야 한다"를 택일이라고 합니다. 이진변수 s로 어느 쪽을 지킬지 고르고, 고르지 않은 쪽을 big-M으로 끕니다.

예를 들어 정수 변수 a, b(둘 다 0부터 9까지)가 서로 달라야 한다고 합시다. "a ≠ b"는 1차 부등식이 아닙니다. 하지만 정수에서는 "a ≥ b + 1 또는 b ≥ a + 1"과 같은 말이므로 택일로 적을 수 있습니다.

a ≥ b + 1 − M·ss = 0이면 켜짐: a가 더 크다
b ≥ a + 1 − M·(1 − s)s = 1이면 켜짐: b가 더 크다

M은 꺼진 쪽이 저절로 성립할 만큼이어야 합니다. s = 1일 때 첫 줄은 a ≥ b + 1 − M인데, 이것이 모든 a, b에서 성립하려면 M ≥ (b + 1 − a의 최댓값) = 9 + 1 − 0 = 10입니다. 둘째 줄도 대칭이라 같습니다. 가장 작은 유효한 M은 10입니다. 컴퓨터로 확인해 봅니다.

for M in range(1, 13):
    ok = True
    for a in range(0, 10):
        for b in range(0, 10):
            if a != b:
                s0 = a >= b + 1 and b >= a + 1 - M
                s1 = a >= b + 1 - M and b >= a + 1
                if not (s0 or s1):
                    ok = False
    print(M, ok)
    if ok:
        break

  • 3~5행 서로 다른 a, b의 짝 90개가 "멀쩡한 답"입니다. 이것들이 하나도 잘리지 않아야 합니다.
  • 6행 s = 0을 넣었을 때 두 줄이 모두 성립하는지 봅니다.
  • 7행 s = 1을 넣었을 때 두 줄이 모두 성립하는지 봅니다.
  • 8~9행 s를 어느 쪽으로 골라도 안 되는 짝이 있으면 그 M은 멀쩡한 답을 자르는 것입니다.
  • 10~12행 처음으로 통과한 M에서 멈춥니다. 10입니다.

반대 방향(a = b인 엉터리 답을 들이지 않는가)은 M과 상관없이 성립합니다. s = 0이면 첫 줄이 a ≥ b + 1을, s = 1이면 둘째 줄이 b ≥ a + 1을 요구하니 a = b는 어느 쪽으로도 통과하지 못합니다.

곱, 절댓값, 최댓값

1차식이 아닌 것 가운데 몇 가지는 변수를 하나 더 두어 1차식으로 바꿀 수 있습니다.

이진변수 둘의 곱

w = a × b(a, b는 이진변수)는 a와 b가 둘 다 1일 때만 1입니다. 「한 방향과 양방향」의 표에서 본 "둘 다 하면 1"과 같습니다.

w ≤ a,   w ≤ b,   w ≥ a + b − 1,   w ≥ 0

(a, b) = (1, 1)이면 셋째 식에서 w ≥ 1, 첫째 식에서 w ≤ 1이라 w = 1입니다. 나머지 세 경우에는 첫째나 둘째 식에서 w ≤ 0이고 넷째 식에서 w ≥ 0이라 w = 0입니다.

이진변수와 실수 변수의 곱

w = x × z(x는 이진변수, z는 0 ≤ z ≤ U인 실수 변수)는 "스위치가 켜지면 z, 꺼지면 0"입니다.

w ≤ U·x,   w ≤ z,   w ≥ z − U(1 − x),   w ≥ 0

x = 0이면 첫째와 넷째 식에서 w = 0이고, 셋째 식은 w ≥ z − U(오른쪽이 0 이하)라 저절로 성립합니다. x = 1이면 둘째와 셋째 식에서 w = z이고, 첫째 식 w ≤ U는 저절로 성립합니다. 실수 변수끼리의 곱은 이런 식으로 정확히 적을 수 없습니다.

절댓값과 최댓값 줄이기

|a − b|를 작게 만들고 싶다고 합시다. 절댓값은 1차식이 아닙니다. 새 변수 t를 두고 다음처럼 적습니다.

최소화 t,    t ≥ a − b,   t ≥ b − a

두 식은 "t는 |a − b| 이상"이라는 한 방향만 말합니다. 나머지 방향은 최소화가 채웁니다. 「쓸모없는 스위치는 꺼진다」와 같은 원리입니다. 최댓값도 마찬가지입니다. T1, T2, T3 가운데 가장 큰 값을 작게 만들고 싶으면 "최소화 t, t ≥ T1, t ≥ T2, t ≥ T3"로 적습니다.

이 요령은 그 양을 작게 만들고 싶을 때만 통합니다. 절댓값을 크게 만들고 싶을 때 같은 식을 쓰면 t가 V자 위쪽으로 끝없이 올라가 버립니다. 그럴 때는 이진변수로 "어느 쪽이 더 큰가"를 골라야 합니다(택일).

가이드와 연결

가이드가 tryAgain 모형의 제약을 설명할 때 쓰는 "x이면 y", "많아야 하나", "a이면 b 또는 c"는 모두 이 장 2부의 표에 있는 꼴입니다. 특히 접근 가능성을 전파하는 제약은 yi ≤ (아래 이웃들의 y의 합)인데, 이것은 "a ≤ b + c", 곧 "i가 접근 가능하면 아래 이웃 가운데 적어도 하나가 접근 가능하다"입니다. 다음 장에서 한 줄씩 읽습니다.

가이드는 1등 풀이의 좋은 점으로 "big-M이 없다"를 듭니다. 그 뜻은 이 장 3부의 「M이 크면 왜 나쁜가」입니다. 반대로 택배 트럭 경로 문제를 보통의 방법으로 적으면 「배달 시각의 예」의 big-M이 꼭 들어갑니다.

가이드가 "접근 가능한데 y = 0인 것은 허용된다", "y는 목적함수에 없다"고 말하는 대목은 「쓸모없는 스위치는 꺼진다」의 경고(비용이 0인 스위치)에 해당합니다.

  • 이진변수는 0 아니면 1인 스위치입니다. 정수 조건이 붙으면 문제는 어려워지지만 표현력이 커집니다.
  • 맞게 적었다 = 엉터리 답을 들이지 않는다 + 멀쩡한 답을 잘라 내지 않는다. 진리표로 두 방향을 한꺼번에 확인합니다.
  • 「또는」으로 이은 조건은 "참인 조건의 개수 ≥ 1"로 적습니다. "a이면 b"는 a ≤ b입니다.
  • 뜻이 같은 식이 여럿일 수 있고, 정수 조건을 지운 LP에서는 서로 다릅니다.
  • 비용이 있는 스위치는 쓸모없으면 저절로 꺼지므로 한 방향만 적어도 됩니다.
  • big-M은 스위치로 제약을 켜고 끄는 요령입니다. M은 유효한 것 가운데 가장 작게 잡습니다.

연습문제

이진변수 a, b, c, d에 대해 "a를 하면 b와 c 가운데 하나는 해야 하고, d는 하면 안 된다"를 부등식으로 적으세요.

두 조건으로 나눕니다. "a이면 b 또는 c"는 "a를 안 하거나 b를 하거나 c를 한다"이므로 (1 − a) + b + c ≥ 1, 곧 a ≤ b + c. "a이면 d를 안 한다"는 "a를 안 하거나 d를 안 한다"이므로 (1 − a) + (1 − d) ≥ 1, 곧 a + d ≤ 1. 답은 두 줄 a ≤ b + c, a + d ≤ 1입니다.

"a와 b 가운데 정확히 하나만 한다"를 1차식으로 적고 진리표로 확인하세요.

a + b = 1입니다. (0, 0): 0 = 1 위반. (0, 1): 성립. (1, 0): 성립. (1, 1): 2 = 1 위반. "정확히 하나"가 참인 두 경우와 정확히 일치합니다. 부등식만 쓰고 싶으면 a + b ≥ 1(적어도 하나)과 a + b ≤ 1(많아야 하나) 두 줄로 적으면 됩니다.

본문의 진리표 코드를 고쳐서, "a와 b를 다 하면 c도 한다"와 부등식 c ≥ a + b − 1이 같은 뜻인지 확인하려면 5행과 6행을 어떻게 바꿔야 하나요? 결과에서 False가 나오는 줄은 어디인가요?

5행을 logic = (a == 0) or (b == 0) or (c == 1)로, 6행을 ineq = c >= a + b - 1로 바꿉니다. 말이 거짓이 되는 것은 a = b = 1인데 c = 0인 한 줄(1 1 0)뿐이고, 그 줄에서 부등식도 0 ≥ 1로 위반이라 두 열이 False, False로 같습니다. 마지막 줄에는 True가 출력됩니다.

c = "a나 b 가운데 하나라도 하면 1"을 세 부등식으로 정의하세요. c를 이진변수가 아니라 0 ≤ c ≤ 1인 실수 변수로 두어도, a와 b가 이진변수이면 c가 저절로 0 또는 1이 되는지 따져 보세요.

c ≥ a, c ≥ b, c ≤ a + b. a = b = 0이면 c ≤ 0이고 c ≥ 0이라 c = 0. a나 b 가운데 하나라도 1이면 c ≥ 1이고 c ≤ 1이라 c = 1. 따라서 c는 정수 조건 없이도 0 또는 1로 정해집니다. 다만 상한 c ≤ 1이 꼭 있어야 합니다. a = b = 1이면 셋째 식은 c ≤ 2밖에 말해 주지 않기 때문입니다.

배달 시각의 예에서 bi = 30, si = 5, τij = 8, aj = 40이면 가장 작은 유효한 M은 얼마인가요? bi가 20으로 바뀌면 어떻게 되나요?

M = 30 + 5 + 8 − 40 = 3. 검산: xij = 0이고 가장 나쁜 경우인 ti = 30, tj = 40을 넣으면 오른쪽이 30 + 13 − 3 = 40이라 40 ≥ 40으로 딱 성립합니다. bi = 20이면 M = 33 − 40 = −7로 0 이하입니다. i를 가장 늦게 떠나도 33분에 도착하는데 j의 시간창은 40분에 열리므로, tj ≥ ti + si + τij가 xij와 상관없이 언제나 성립합니다. 이 제약은 적지 않아도 됩니다.

정수 변수 a, b가 0부터 5까지의 값을 가질 때, "a ≠ b"를 택일로 적으려면 가장 작은 유효한 M은 얼마인가요? 본문의 코드를 어떻게 고치면 확인할 수 있나요?

M ≥ (b + 1 − a의 최댓값) = 5 + 1 − 0 = 6이므로 M = 6입니다. 코드에서는 3행과 4행의 range(0, 10)을 range(0, 6)으로 바꾸면 되고, 출력은 1부터 5까지 False, 6에서 True입니다.

창고 예에서 창고를 여는 비용이 100이 아니라 0이라면, "쓸모없는 스위치는 꺼진다"의 「왜 그런가」 가운데 어느 문장이 성립하지 않게 되나요?

"그런데 비용은 100만큼 줄었습니다"가 성립하지 않습니다. y를 1에서 0으로 바꿔도 비용이 그대로이므로, 처음 답이 최적해가 아니라고 말할 수 없습니다. x가 모두 0이고 y = 1인 답과 y = 0인 답이 똑같이 최적입니다. 그래서 솔버가 내놓은 답에서 y = 1이라고 해서 "이 창고는 쓰인다"고 읽으면 안 됩니다.

이진변수 x와 0 ≤ z ≤ 40인 실수 변수 z의 곱 w = x·z를 적은 네 식에 (x, z) = (1, 25)와 (0, 25)를 넣어, w가 각각 얼마로 정해지는지 확인하세요.

U = 40입니다. (1, 25): w ≤ 40, w ≤ 25, w ≥ 25 − 0 = 25, w ≥ 0이므로 w = 25. (0, 25): w ≤ 0, w ≤ 25, w ≥ 25 − 40 = −15, w ≥ 0이므로 w = 0. 두 경우 모두 w = x·z와 같습니다.

"최소화 t, t ≥ a − b, t ≥ b − a"에서 목적함수를 "최대화 t"로 바꾸면 무슨 일이 생기나요? 6장의 말로 답하세요.

두 식은 t의 아래쪽만 막고 위쪽은 막지 않습니다. 그래서 t를 끝없이 키울 수 있고, 문제는 비유계가 됩니다(a, b가 무엇이든). t가 |a − b|와 같아지는 것은 최소화가 t를 끌어내려 주기 때문이었습니다. 절댓값을 크게 만들고 싶다면 이진변수로 "a − b가 양수인 쪽"과 "음수인 쪽"을 고르는 택일로 적어야 합니다.
