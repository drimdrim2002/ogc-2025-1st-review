2부 · 입력: 무엇이 주어지는가

문제 하나는 dict 하나

문제는 파일 하나로 주어지고, 프로그램에는 그 파일을 읽은 Python의 dict가 넘어옵니다. dict(딕셔너리)는 리스트와 비슷한데, 번호 대신 이름표로 값을 꺼내는 자료형입니다. 리스트 a에서 a[0]으로 첫 값을 꺼내듯이, dict prob_info에서는 prob_info['N']으로 'N'이라는 이름표가 붙은 값을 꺼냅니다. 이름표를 키(key)라고 부릅니다.

1장의 미니 문제 B를 대회의 입력 모양으로 적으면 다음과 같습니다.

prob_info = {
    "N": 3,                        # 노드 3개: 출입구 0, 칸 1, 칸 2
    "E": [[0, 1], [1, 2]],         # 간선 2개: 0과 1 사이, 1과 2 사이
    "P": 4,                        # 항구 4개: 0, 1, 2, 3
    "K": [
        [[0, 2], 1],               # 수요 0: 항구 0에서 실어 항구 2에서 내릴 차 1대 (차 A)
        [[1, 3], 1]                # 수요 1: 항구 1에서 실어 항구 3에서 내릴 차 1대 (차 B)
    ],
    "F": 10,                       # 고정비
    "LB": 44                       # 4부에서 설명
}
키값의 모양내용
N정수노드의 수. 노드 번호는 0부터 N−1까지이고 0이 출입구입니다. 차를 세울 수 있는 칸은 1부터 N−1까지, N−1개입니다.
E[u, v]의 리스트간선 목록. [0, 1]은 노드 0과 1 사이에 통로가 있다는 뜻이고, 양쪽 방향으로 다 지나갈 수 있습니다. 한 간선은 한 번만 적혀 있습니다.
P정수항구의 수. 배는 0, 1, …, P−1 순서로 들릅니다.
K[[o, d], r]의 리스트수요 목록. "항구 o에서 실어 항구 d에서 내릴 차 r대". 항상 o < d입니다. 리스트에서 몇 번째인지가 곧 수요 번호입니다(0부터 셉니다).
F정수경로 하나마다 붙는 고정비.
LB수주최 측이 미리 계산해 넣어 주는 기준값. 4부에서 설명합니다.
grid_graph(생략)배를 그림으로 그리기 위한 부가 정보. 풀이에는 필요 없습니다.

이런 파일 형식을 JSON이라고 합니다. Python의 dict, 리스트, 숫자를 글자로 적어 놓은 것과 거의 같은 모양이라 Python으로 읽기 쉽습니다. 대회 사이트에 실린 실제 문제 파일의 앞부분은 이렇게 생겼습니다.

{
  "N": 49,
  "E": [ [0, 1], [1, 2], [2, 3], [2, 4], ... ],
  "P": 10,
  "K": [
    [ [0, 1], 4 ],     ← 수요 0: 항구 0에서 실어 항구 1에서 내릴 차 4대
    [ [0, 2], 3 ],     ← 수요 1: 항구 0 → 항구 2, 3대
    [ [0, 3], 2 ],     ← 수요 2: 항구 0 → 항구 3, 2대
    ...
  ],
  "F": 100,
  "LB": 13259,
  "grid_graph": ...
}

같은 수요의 차는 서로 구별하지 않습니다. 수요 0의 차 4대는 모두 같은 차로 칩니다. 그래서 답을 낼 때 "몇 번째 차"가 아니라 "몇 번 수요의 차"인지만 적습니다. 이 점은 뒤에서 풀이가 단순해지는 이유 가운데 하나입니다. 차를 한 대씩 따로 따라다니지 않고 "이 항구에서 저 항구까지 가는 차가 몇 대"만 세면 되기 때문입니다(8장).

3부 · 출력: 답을 어떻게 적어 내는가

해는 항구별 경로 목록

최적화 문제의 답을 해(solution)라고 부릅니다. 이 대회의 해는 항구마다 [경로, 수요 번호]를 실행할 순서대로 늘어놓은 목록입니다. 미니 문제 B의 해 (가)를 이 모양으로 적으면 다음과 같습니다. 차 A가 수요 0, 차 B가 수요 1입니다.

solution = {
    0: [ [[0, 1], 0] ],                                  # 항구 0: A를 칸 1에 싣는다
    1: [ [[1, 0], 0], [[0, 1, 2], 1], [[0, 1], 0] ],     # 항구 1: A를 잠깐 내리고, B를 칸 2에, A를 다시 칸 1에
    2: [ [[1, 0], 0] ],                                  # 항구 2: A를 내린다
    3: [ [[2, 1, 0], 1] ]                                # 항구 3: B를 내린다
}

이것도 dict입니다. 키가 항구 번호이고 값이 그 항구의 목록입니다. 경로가 선적인지 하역인지는 적지 않습니다. 채점기가 0이 어디에 있는지를 보고 판단합니다.

종류모양실행하는 순간에 지켜야 할 조건
선적 경로[0, …, i]
첫 노드가 0		경로 위의 모든 칸(마지막 칸 i 포함)에 차가 없어야 합니다. 실행하면 칸 i에 차가 놓입니다.
하역 경로[i, …, 0]
마지막 노드가 0		첫 칸 i에는 내릴 차가 있어야 하고, 나머지 칸에는 차가 없어야 합니다. 실행하면 칸 i가 빕니다.
위치변경 경로[i, …, j]
0이 양 끝에 없음		첫 칸 i에는 옮길 차가 있고, 나머지 칸(마지막 칸 j 포함)은 비어 있어야 합니다.

종류와 상관없이 모든 경로는 다음을 지켜야 합니다.

  • 노드가 둘 이상이고, 모든 노드 번호가 0부터 N−1 사이에 있습니다.
  • 이웃한 두 노드 사이에 실제로 간선이 있습니다. 통로가 없는 곳을 건너뛸 수 없습니다.
  • 같은 노드를 두 번 지나지 않습니다.

임시 하역 후 재적재는 따로 종류가 있는 것이 아니라, 하역 경로 하나와 선적 경로 하나를 각각 적는 것입니다. 위 해의 항구 1에서 [[1, 0], 0]과 [[0, 1], 0]이 그 쌍입니다.

채점기가 하는 일

채점기는 항구 0의 목록을 앞에서부터 하나씩 실행하고, 다음에 항구 1의 목록을 실행하는 식으로 끝까지 갑니다. 칸마다 "지금 어느 수요의 차가 있는가"를 적어 두고, 경로 하나를 실행할 때마다 규칙을 검사하고 장부를 고칩니다. 이 일을 Python으로 짧게 흉내 내면 다음과 같습니다. 선적과 하역만 다루는 작은 채점기입니다.

def check(N, F, solution):
    cell = [-1] * N
    total = 0
    for port in range(len(solution)):
        for route, k in solution[port]:
            if route[0] == 0:
                for i in route[1:]:
                    if cell[i] != -1:
                        return "무효: 길에 차가 있음"
                cell[route[-1]] = k
            else:
                if cell[route[0]] == -1:
                    return "무효: 내릴 차가 없음"
                for i in route[1:]:
                    if cell[i] != -1:
                        return "무효: 길에 차가 있음"
                cell[route[0]] = -1
            total = total + F + len(route) - 1
    return total
  • 2 cell[i]는 칸 i에 있는 차의 수요 번호입니다. 비어 있으면 −1입니다. 처음에는 모두 비어 있습니다.
  • 4~5 항구를 차례로, 그 항구의 (경로, 수요 번호)를 차례로 꺼냅니다. for route, k in …는 [경로, 수요 번호] 한 쌍을 두 변수에 나눠 담는 표기입니다.
  • 6~10 첫 노드가 0이면 선적입니다. 출입구를 뺀 경로 위의 모든 칸(route[1:])이 비어 있는지 보고, 마지막 칸(route[-1])에 수요 k의 차를 놓습니다.
  • 11~17 아니면 하역입니다. 첫 칸에 차가 있는지, 나머지 길이 비어 있는지 보고, 첫 칸을 비웁니다. 수요 번호 k는 여기서 쓰이지 않습니다.
  • 18 비용을 더합니다. 간선의 수는 노드의 수에서 1을 뺀 값입니다.

미니 문제 B의 해 (가)를 넣으면 68이 나옵니다. 항구 1의 순서를 바꿔 B를 먼저 실으려 하면([0, 1, 2]를 맨 앞으로) 무효가 나옵니다.

68
무효: 길에 차가 있음

주최 측의 진짜 채점 코드(util.py의 check_feasibility, 핵심은 40줄 남짓)는 같은 뼈대에 다음 검사들이 더 붙어 있습니다.

  • 위에서 말한 공통 검사(노드 둘 이상, 번호 범위, 같은 노드를 두 번 지나지 않음, 간선이 실제로 있음)와 위치변경 경로의 처리.
  • 항구를 떠날 때의 검사. 한 항구의 목록을 다 실행한 뒤, 배에 있는 차를 수요 번호별로 세어서 "그 항구를 떠날 때 타고 있어야 할 차"와 정확히 같은지 봅니다. 항구 p를 떠날 때는 o ≤ p < d인 수요의 차가 수요별로 정확히 r대씩 있어야 합니다. 실어야 할 차를 안 실었거나, 잠깐 내린 차를 다시 싣지 않고 떠나면 여기서 걸립니다.

모든 경로가 규칙을 지키고 이 검사도 모든 항구에서 통과하면 유효해(feasible solution), 하나라도 어기면 무효해입니다. 채점 코드에서 읽을 수 있는, 문제 설명에는 분명히 적혀 있지 않은 사실 세 가지를 적어 둡니다.

  • 경로의 종류는 양 끝만 보고 정합니다. 첫 노드가 0이면 선적, 마지막 노드가 0이면 하역, 둘 다 아니면 위치변경입니다.
  • 수요 번호는 선적할 때 칸에 기록됩니다. 하역 경로에서는 "그 칸에 차가 있는가"만 보고, 적어 낸 수요 번호가 그 칸의 차와 같은지는 비교하지 않습니다. 이 사실은 9장에서 다시 나옵니다.
  • 잠깐 내린 차를 다시 실을 때는 원래의 수요 번호로 싣습니다. 그래야 항구를 떠날 때의 검사를 통과합니다.
4부 · 점수: 총비용에서 LB를 뺀다

LB: 아무도 서로를 막지 않는다면

점수로 쓰는 값은 총비용 그 자체가 아니라, 총비용에서 LB라는 기준값을 뺀 것입니다. LB는 "차들이 서로 길을 막지 않는다고 치면 적어도 얼마가 드는가"입니다. 문제 설명의 정의를 옮기면 이렇습니다.

LB = 항구마다 다음을 구해 모두 더한 값
  F × (싣는 차의 수 + 내리는 차의 수)경로마다 고정비
  + 출입구에서 가장 가까운 칸부터 (싣는 차의 수)개의 거리 합선적 경로의 길이
  + 출입구에서 가장 가까운 칸부터 (내리는 차의 수)개의 거리 합하역 경로의 길이

여기서 거리는 출입구에서 그 칸까지 가장 짧게 갈 때 지나는 간선의 수입니다. 일렬 배에서 칸 1의 거리는 1, 칸 2의 거리는 2입니다. "싣는 차"는 그 항구가 출발 항구인 차, "내리는 차"는 그 항구가 도착 항구인 차이고, 재배치는 한 번도 없다고 칩니다.

미니 문제 B로 계산해 봅니다. 항구마다 차가 한 대씩 타거나 내립니다.

항구싣는 차내리는 차계산값
01대 (A)0대10 × 1 + (1) + 011
11대 (B)0대10 × 1 + (1) + 011
20대1대 (A)10 × 1 + 0 + (1)11
30대1대 (B)10 × 1 + 0 + (1)11
LB44

이 계산은 무척 낙관적입니다. 항구마다 배가 텅 비어 있는 것처럼, 차가 탈 때도 내릴 때도 칸 1을 쓴다고 칩니다. A와 B가 동시에 칸 1에 있을 수 없다는 것도, 막힘 때문에 재배치가 필요하다는 것도 따지지 않습니다. 그래서 실제로는 이 값에 닿을 수 없는 경우가 대부분입니다. 미니 문제 B의 가장 싼 해는 68이었습니다.

LB는 lower bound, 우리말로 하한의 줄임말입니다. "어떤 유효해의 총비용도 이 값보다 작을 수 없다"는 뜻입니다. 차마다 선적 경로와 하역 경로가 하나씩은 꼭 필요하고, 그 길이는 가장 가까운 칸들을 썼을 때보다 짧을 수 없기 때문입니다. 하한이라는 말은 5장에서 다른 뜻으로 한 번 더 나오므로, 대회가 준 이 값은 앞으로 대회 LB라고 부르겠습니다.

공식 예시에서도 계산해 봅니다. 칸 1, 2, 3, 4의 거리는 1, 2, 3, 4입니다.

31대2대10 × 3 + (1) + (1 + 2)34
40대2대10 × 2 + 0 + (1 + 2)23
LB137

입력 파일의 "LB": 137이 이 값입니다.

목적함수 = 총비용 − LB

최적화 문제에서 작게(또는 크게) 만들려는 값을 목적함수(objective function)라고 합니다. 이 대회의 목적함수는 다음과 같습니다.

목적함수 = (모든 경로 비용의 합) − LB

LB는 문제마다 정해진 수이므로, 목적함수를 가장 작게 만드는 것과 총비용을 가장 작게 만드는 것은 같은 일입니다. LB를 빼는 까닭은 "어차피 드는 기본 비용"을 걷어 내고, 막힘 때문에 추가로 든 비용만 비교하려는 것입니다. 목적함수가 0이면 아무도 서로를 막지 않은 완벽한 해입니다. 미니 문제 B의 목적함수는 68 − 44 = 24이고, 미니 문제 A는 46 − 45 = 1입니다.

5부 · 실행 환경과 순위

프로그램은 어떻게 실행되는가

참가자는 myalgorithm.py라는 파일에 algorithm(prob_info, timelimit)이라는 Python 함수를 만들어 냅니다. 주최 측은 문제의 dict와 제한 시간(초)을 넣어 이 함수를 부르고, 함수는 위에서 본 모양의 해(dict)를 돌려줍니다.

항목내용
컴퓨터주최 측의 서버(AWS c5.4xlarge, 16코어, 메모리 32GB, Ubuntu 24.04). 프로그램은 그중 최대 4코어만 쓸 수 있고, 인터넷에는 접속할 수 없습니다. 코어는 동시에 계산할 수 있는 일꾼의 수라고 보면 됩니다.
언어부르는 입구는 Python 3.11의 algorithm() 함수입니다. 다른 언어로 짠 부분은 미리 실행 파일로 만들어 함께 내고 Python에서 부릅니다. tryAgain은 속도가 빠른 C++라는 언어로 알맹이를 짰습니다(3장, 10장).
쓸 수 있는 도구최적화 문제를 풀어 주는 프로그램인 솔버(solver) 세 가지가 설치되어 있었습니다. gurobipy 12.0.1, ortools 9.11, xpress 9.5.4입니다. 솔버가 무엇인지는 3~5장에서 설명합니다.
시간 제한문제마다 다릅니다(1부의 표). timelimit 인자로 전달되고, 넘기면 그 문제는 벌점입니다.
문제 크기결선 평가 문제는 노드 400개 이하라고 공지되었습니다.

순위는 「나보다 잘한 팀 수」로 매긴다

문제마다 점수를 매겨 더합니다. 평가받는 팀의 수를 R, 그 문제에서 나보다 더 작은(좋은) 목적함수를 낸 팀의 수를 n이라고 하면 점수는 다음과 같습니다.

점수 = R − n해가 유효할 때 (0보다 작아지면 0)
점수 = −1무효해, 시간 초과, 실행 오류일 때

10팀이 겨루는 문제에서 나보다 잘한 팀이 3팀이면 7점, 내가 가장 잘했으면 10점입니다. 이 방식에는 두 가지 성질이 있습니다.

  • 차이의 크기는 상관없고 순서만 중요합니다. 1만큼 이기나 1000만큼 이기나 점수는 같습니다. 반대로 1만큼만 져도 한 팀에게 진 것입니다.
  • 무효해는 꼴찌보다 나쁩니다. 그래서 어떤 문제가 와도 유효해를 내는 안정성이 중요합니다.

결선은 본선에 마지막으로 낸 프로그램을 그대로 새 문제 14개에 돌려 평가했습니다. 최종 순위는 이 점수를 80점 만점으로, 발표 평가를 20점 만점으로 바꿔 더해서 정했습니다.

6부 · 문제의 성격

왜 어려운가

  • 정할 것이 세 겹입니다. 어느 칸에 세울지(배치), 어떤 길로 갈지(경로), 어떤 차례로 실행할지(순서)를 함께 정해야 하고 셋이 서로 얽혀 있습니다.
  • 항구들이 이어져 있습니다. 항구 0에서 차를 어디에 세웠느냐가 항구 3에서의 재배치를 정합니다. 미니 문제 B에서 (가)와 (나)는 항구 0에서 이미 갈렸습니다. 항구별로 따로따로 풀 수 없습니다.
  • 빈칸이 넉넉하지 않습니다. 대회 문제의 수요는 어느 때에도 배의 칸 수를 넘지 않게, 그리고 미리 정한 비율만큼 배를 채우도록 무작위로 만들어졌습니다(대회 사이트 「문제 생성 방법」. 그 비율을 정하는 값의 이름은 total_allocation_ratio이고, 문제별 값은 공개된 설명에 없습니다). 공식 예시처럼 배가 꽉 차면 위치변경할 빈칸조차 없습니다.
  • 고정비가 큽니다. 실제 문제에서 F는 100 이상입니다. 재배치 한 번이 경로를 수십 칸 줄이는 것보다 비쌉니다. 재배치 횟수가 한 번만 달라져도 순위가 갈립니다.
  • 경우의 수가 폭발합니다. 칸 4개짜리 공식 예시는 손으로도 풀 수 있습니다. 하지만 서로 다른 차 100대를 칸 100개에 한 대씩 세우는 방법만 해도 100! ≈ 9 × 10157가지입니다. 1초에 10억 가지씩 살펴봐도 우주의 나이로는 턱없이 모자랍니다. 다 해 보는 방법은 쓸 수 없습니다.

다음 장에서 1등 팀이 이 문제를 어떻게 바라봤는지를 식 없이 먼저 봅니다.

이해 확인

공식 예시에서 수요 번호 3은 어떤 차인가요?

K의 네 번째 항목 [[1, 3], 1]입니다. 항구 1에서 실어 항구 3에서 내릴 차 1대입니다. 수요 번호는 K 리스트에서의 순번이고 0부터 셉니다.

미니 문제 A(차 A는 항구 0 → 2, 차 B는 항구 0 → 1, 일렬 배의 칸 2개, F = 10)의 LB를 계산해 보세요.

항구 0에서 2대를 싣습니다: 10 × 2 + (1 + 2) = 23. 항구 1에서 1대를 내립니다: 10 + 1 = 11. 항구 2에서 1대를 내립니다: 10 + 1 = 11. 합은 45입니다. 1장에서 구한 가장 싼 해가 46이었으니 목적함수는 1입니다. 이 1은 항구 2에서 A가 칸 1이 아니라 칸 2에서 내린 몫입니다.

미니 문제 B의 해 (나)를 대회의 출력 모양(dict)으로 적어 보세요.

{0: [[[0,1,2], 0]], 1: [[[0,1], 1]], 2: [[[1,0], 1], [[2,1,0], 0], [[0,1], 1]], 3: [[[1,0], 1]]}입니다. 항구 2의 첫 경로와 셋째 경로가 차 B(수요 1)를 잠깐 내렸다 다시 싣는 쌍입니다.

목적함수가 음수가 될 수 있나요?

없습니다. LB는 어떤 유효해의 총비용보다도 작거나 같게 만들어져 있습니다. 차마다 선적 경로와 하역 경로가 하나씩은 필요하고, 그 길이는 가장 가까운 칸들을 썼을 때보다 짧을 수 없기 때문입니다.

40팀이 겨루는 문제에서 내 목적함수는 1,750이고, 1,724를 낸 팀이 한 팀, 나머지는 모두 나보다 큽니다. 내 점수는? 내 값이 1,725였다면?

나보다 잘한 팀이 한 팀이므로 40 − 1 = 39점입니다. 1,725였어도 1,724보다 크므로 똑같이 39점입니다. 점수는 차이의 크기가 아니라 순서로 정해집니다.

어떤 해가 항구 1에서 차 한 대를 잠깐 내린 뒤 다시 싣지 않고 떠났습니다. 채점기의 어느 검사에 걸리나요?

항구를 떠날 때의 검사입니다. 항구 1을 떠날 때 배에 있어야 할 차의 수요별 대수와 실제로 배에 있는 차가 맞지 않습니다.

  • 문제는 dict 하나로 주어집니다. N(노드 수), E(간선 목록), P(항구 수), K(수요 목록), F(고정비), LB.
  • 해는 항구별로 [경로, 수요 번호]를 실행 순서대로 적은 목록입니다. 채점기는 그것을 차례로 실행하며 규칙을 검사합니다.
  • 대회 LB는 "아무도 서로를 막지 않고 늘 가장 가까운 칸을 쓴다"고 쳤을 때의 비용이고, 목적함수는 총비용 − LB입니다.
  • 공식 예시(N = 5, P = 5, F = 10, LB = 137)의 예시 해는 194, 더 싼 해는 190입니다.
  • 점수는 "나보다 잘한 팀 수"로 정해지고, 무효해는 벌점입니다.
