문제 이해: 배 안 어디에 차를 세우고, 어떤 순서로 넣고 뺄 것인가

자동차 운반선은 여러 항구를 차례로 들르며 차를 싣고 내립니다. 배 안은 좁은 통로로 이어져 있어서, 안쪽 차를 내리려면 길을 막고 있는 바깥쪽 차를 먼저 치워야 합니다. 이 문제는 각 차를 배 안 어느 칸에 세울지, 그리고 항구마다 어떤 순서와 경로로 차를 움직일지를 정해서 전체 이동 비용을 최소로 만드는 문제입니다.

이 장은 풀이 이야기를 하지 않습니다. 입력이 어떻게 생겼는지를 실제 데이터 모양으로 먼저 보고, 지켜야 할 규칙, 비용 계산, 출력 형식, 채점 방식을 차례로 봅니다. 내용은 대회 사이트의 「문제 설명 및 순위 결정 방법」, 「개발 환경 및 베이스라인 알고리즘」 페이지와, 주최 측이 배포한 채점 코드 util.py의 check_feasibility 함수를 대조해서 정리했습니다.

이 문서를 읽는 법. 이 문서는 대회 사이트, 팀의 발표자료, 소스 코드를 보지 않고도 읽을 수 있게 썼습니다. 본문에 나오는 "발표자료 3쪽", "function.cpp 80~94줄" 같은 표시는 그 내용이 어디서 왔는지를 밝히는 출처이지, 찾아서 읽어야 한다는 뜻이 아닙니다. 설명에 필요한 그림, 표, 수식, 코드는 모두 이 문서 안에 옮겨 놓았습니다. 코드는 설명하는 부분만 발췌했고, 줄인 곳은 ...이나 "(요지)"로 표시했습니다. 각 장 끝의 「이 장의 참고자료」는 더 공부하고 싶을 때를 위한 것이고, 항목 앞의 작은 딱지는 무료 누구나 볼 수 있음, 교과서 유료 책, 유료 구독이 필요한 논문, 한국어 한국어 자료, 실습 코드를 따라 칠 수 있음을 뜻합니다.

1부 · 상황과 용어

배 안은 그래프다

대회 이름의 Roll-on Roll-off(RORO)는 차가 제 바퀴로 굴러 들어가고 굴러 나오는 선박을 말합니다. 문제는 배의 내부를 deck graph라는 그래프로 표현합니다.

용어뜻
노드(node)차 한 대를 세울 수 있는 칸. 한 노드에는 차가 한 대만 들어갑니다.
간선(edge)두 칸 사이를 차가 지나다닐 수 있다는 뜻. 방향이 없고 길이는 모두 1입니다.
출입구(gate)항상 노드 0. 배와 항구를 잇는 유일한 문입니다. 출입구에는 차를 세울 수 없습니다.
항구(port)배는 항구 0, 1, …, P−1을 이 순서로 한 번씩 들릅니다. 항로는 주어져 있고 바꿀 수 없습니다.
수요(demand)"항구 o에서 실어 항구 d에서 내릴 차 r대". (출발 항구, 도착 항구, 대수)로 주어집니다. 항상 o < d입니다.
선적(loading)항구에서 출입구를 거쳐 배 안의 빈 노드까지 차를 몰고 들어가는 것.
하역(unloading)배 안의 노드에서 출입구를 거쳐 항구로 차를 몰고 나오는 것.
재배치(rehandling)도착 항구가 아닌 곳에서 차를 움직이는 것. 방법이 두 가지입니다(아래).

실제 문제의 그래프에는 제약이 없습니다. 트리(순환이 없는 그래프)가 아니어도 되고, 격자처럼 순환이 있어도 되고, 평면 그래프(간선이 서로 교차하지 않게 종이 위에 그릴 수 있는 그래프)가 아니어도 됩니다. 대회 문제는 여러 층의 격자를 경사로(ramp)로 잇고 일부 칸을 장애물로 지운 모양으로 생성되었습니다(대회 사이트 「문제 생성 방법」).

막힌 차를 치우는 두 가지 방법

(가)에서 노드 5의 차를 내려야 하는데 노드 2에 다른 차가 서 있다고 합시다. 노드 2의 차는 아직 도착 항구가 아니지만 치워야 합니다. 문제는 두 가지 방법을 허용합니다.

  • 위치변경(relocation). 배 안에서 다른 빈 칸으로 옮깁니다. 예: 2 → 3. 경로 하나로 끝납니다.
  • 임시 하역 후 재적재. 일단 항구로 내렸다가(2 → 1 → 0) 나중에 다시 싣습니다(0 → … → 빈 칸). 경로가 두 개 생깁니다. 다시 실을 때는 원래와 다른 칸에 세워도 됩니다. 항구에 임시로 내려 둘 수 있는 차의 수에는 제한이 없습니다.

둘 다 비용이 듭니다. 그리고 재배치가 싫다고 차를 안 싣거나 안 내릴 수는 없습니다. 모든 수요는 반드시 출발 항구에서 실려 도착 항구에서 내려져야 합니다.

2부 · 입력: 무엇이 주어지는가

문제 하나는 JSON 파일 하나

문제 하나는 JSON 파일 하나이고, 필드는 일곱 개입니다. 알고리즘에는 이 JSON을 읽은 Python dict(prob_info)가 그대로 넘어옵니다.

키형내용
N정수노드 개수. 노드 번호는 0 ~ N−1이고 0이 출입구입니다. 차를 세울 수 있는 칸은 1 ~ N−1, 즉 N−1개입니다.
E[u, v]의 목록간선 목록. 방향이 없으며 한 간선은 한 번만 적혀 있습니다. [0, 1]이 있으면 0→1, 1→0 둘 다 갈 수 있습니다.
P정수항구 개수. 배는 0, 1, …, P−1 순서로 들릅니다.
K[[o, d], r]의 목록수요 목록. "항구 o에서 실어 항구 d에서 내릴 차 r대". 목록에서의 순번이 곧 수요 번호입니다(0부터).
F정수경로 하나마다 붙는 고정비.
LB수총비용의 하한값. 주최 측이 미리 계산해서 넣어 줍니다(4부에서 설명).
grid_graph객체그림을 그리기 위한 부가 정보. 풀이에는 필요 없습니다.

대회 사이트에 실린 실제 문제 파일의 앞부분은 이렇게 생겼습니다.

{
  "N": 49,
  "E": [ [0, 1], [1, 2], [2, 3], [2, 4], ... ],
  "P": 10,
  "K": [
    [ [0, 1], 4 ],      ← 수요 0: 항구 0에서 실어 항구 1에서 내릴 차 4대
    [ [0, 2], 3 ],      ← 수요 1: 항구 0 → 항구 2, 3대
    [ [0, 3], 2 ],      ← 수요 2: 항구 0 → 항구 3, 2대
    ...
  ],
  "F": 100,
  "LB": 13259,
  "grid_graph": ...
}

같은 수요의 차는 서로 구별하지 않습니다. 수요 0의 차 4대는 모두 같은 차로 취급합니다. 그래서 해를 낼 때 "몇 번째 차"가 아니라 "몇 번 수요의 차"인지만 적으면 됩니다. 이 점은 뒤에서 풀이가 단순해지는 이유 중 하나입니다. 차를 한 대씩 따로 추적하지 않고 "이 구간을 가는 차가 몇 대"만 세면 되기 때문입니다(6장).

이 문서의 예시 문제

대회 문제 설명에 나오는 예시를 입력 형식 그대로 적으면 다음과 같습니다. 배는 위 그림의 (나), 항구는 다섯 개(문제 설명에서는 A~E, 여기서는 0~4), 고정비는 10입니다. 이 문서는 7장까지 이 예시 하나를 계속 씁니다.

{
  "N": 5,
  "E": [[0, 1], [1, 2], [2, 3], [3, 4]],
  "P": 5,
  "K": [
    [[0, 2], 2],   ← 수요 0: 항구 0 → 2, 2대
    [[1, 4], 1],   ← 수요 1: 항구 1 → 4, 1대
    [[2, 3], 1],   ← 수요 2: 항구 2 → 3, 1대
    [[1, 3], 1],   ← 수요 3: 항구 1 → 3, 1대
    [[3, 4], 1]    ← 수요 4: 항구 3 → 4, 1대
  ],
  "F": 10,
  "LB": 137
}

차는 모두 6대이고 칸은 4개입니다. 수요를 항구 축 위에 그리면 어느 시점에 배에 몇 대가 있는지 보입니다.

3부 · 규칙: 경로와 순서

모든 움직임은 「경로」로 적는다

차 한 대를 한 번 움직이는 것을 경로(route)라고 하고, 지나가는 노드 번호의 목록으로 적습니다. 종류는 출입구 0이 어디에 있느냐로 갈립니다.

종류모양그 경로를 실행하는 시점에 만족해야 할 조건
선적 경로[0, …, i]
첫 노드가 0		경로 위의 모든 노드(마지막 노드 i 포함)에 차가 없어야 합니다. 실행하면 노드 i에 차가 놓입니다.
하역 경로[i, …, 0]
마지막 노드가 0		첫 노드 i에는 내릴 차가 있어야 하고, 나머지 노드에는 차가 없어야 합니다. 실행하면 노드 i가 빕니다.
위치변경 경로[i, …, j]
0이 양 끝에 없음		첫 노드 i에는 옮길 차가 있고, 나머지 노드(마지막 j 포함)는 비어 있어야 합니다.

종류와 상관없이 모든 경로는 다음을 지켜야 합니다.

  • 노드가 둘 이상이고, 모든 노드 번호가 0 ~ N−1 안에 있습니다.
  • 이웃한 두 노드 사이에 실제로 간선이 있습니다.
  • 같은 노드를 두 번 지나지 않습니다(simple path).

임시 하역 후 재적재는 따로 종류가 있는 것이 아니라, 하역 경로 하나와 선적 경로 하나를 각각 적는 것입니다.

순서가 곧 해의 일부다

해는 항구마다 (경로, 수요 번호) 쌍의 목록입니다. 채점기는 항구 0의 목록을 앞에서부터 하나씩 실행하고, 다음에 항구 1의 목록을 실행하는 식으로 진행합니다. 경로 하나를 실행할 때마다 배 안의 상태가 바뀌므로, 어떤 경로가 유효한지는 그 경로를 실행하는 순간의 배 상태에 달려 있습니다.

같은 경로 두 개라도 순서를 바꾸면 한쪽은 유효하고 한쪽은 무효가 됩니다. 예시의 배 (나)에 차 두 대를 노드 1과 노드 2에 싣는다고 합시다.

[0,1,2] 먼저, [0,1] 나중

안쪽(노드 2)부터 채우므로 둘 다 유효합니다.

[0,1] 먼저, [0,1,2] 나중

두 번째 경로가 노드 1을 지나야 하는데 이미 차가 있습니다. 무효입니다.

내릴 때는 반대로 바깥쪽(노드 1)부터 내려야 합니다. 한 항구 안에서 선적·하역·재배치 경로를 어떤 순서로 섞든 제약은 없습니다. 유효하기만 하면 됩니다. 임시로 내린 차를 한참 뒤에 다시 실어도 됩니다(단, 같은 항구 안에서).

채점기는 한 항구의 목록을 다 실행한 뒤 한 가지를 더 확인합니다. 그 항구를 떠나는 시점에 배에 있어야 할 차가 정확히 있는가입니다. 항구 p를 떠날 때 배에는 o ≤ p < d인 수요의 차가 수요별로 정확히 r대씩 있어야 합니다. 임시로 내린 차를 다시 싣지 않고 떠나면 여기서 걸립니다.

모든 경로가 유효하고 이 확인도 모든 항구에서 통과하면 유효해(feasible solution)입니다. 그렇지 않으면 무효해(infeasible)입니다. 대회 문서의 용어를 따른 것이고, 3장부터 나오는 최적화 분야의 용어로는 같은 것을 「가능해」, 「불능」이라고 부릅니다. 이 문서에서는 대회의 채점을 말할 때는 유효·무효, 수리 모형을 말할 때는 가능·불능을 쓰지만 뜻은 같습니다.

채점 코드가 실제로 확인하는 것

규칙의 최종 기준은 주최 측이 배포한 채점 코드입니다. 핵심은 40줄 남짓이고, 아래는 선적 경로와 하역 경로를 처리하는 부분을 줄여 옮긴 것입니다(util.py의 check_feasibility). node_allocations[i]는 칸 i에 있는 차의 수요 번호이고, 비어 있으면 −1입니다.

for p in range(P):                                  # 항구를 순서대로
    for route, k in solution[p]:                    # 그 항구의 (경로, 수요 번호)를 순서대로
        # 공통 검사: 노드 2개 이상, 번호 범위, 같은 노드를 두 번 지나지 않음
        if route[0] == 0:                           # ── 선적 경로
            loading_node = route[-1]
            if node_allocations[loading_node] != -1:        → 무효 (도착 칸에 이미 차가 있음)
            for i in route[:-1]:
                if node_allocations[i] != -1:               → 무효 (가는 길이 막힘)
            # 이웃한 두 노드 사이에 간선이 있는지 검사
            node_allocations[loading_node] = k              # 그 칸에 수요 k의 차를 놓는다
        elif route[-1] == 0:                        # ── 하역 경로
            unloading_node = route[0]
            if node_allocations[unloading_node] == -1:      → 무효 (내릴 차가 없음)
            for i in route[1:]:
                if node_allocations[i] != -1:               → 무효 (나가는 길이 막힘)
            # 간선 검사
            node_allocations[unloading_node] = -1           # 그 칸을 비운다
        else:                                       # ── 위치변경 경로 (0이 양 끝에 없음)
            ...
        obj += F + len(route) - 1                   # 비용 누적: 고정비 + 간선 수

    # 항구 p의 경로를 다 실행한 뒤: 배에 있는 차를 수요 번호별로 세어
    # "o ≤ p < d인 수요 k가 정확히 r대씩"과 같은지 비교. 다르면 무효

코드에서 읽을 수 있는, 문제 설명에는 분명히 적혀 있지 않은 사실 세 가지를 적어 둡니다.

  • 경로의 종류는 양 끝만 보고 정합니다. 첫 노드가 0이면 선적, 마지막 노드가 0이면 하역, 둘 다 아니면 위치변경입니다.
  • 수요 번호 k는 선적할 때 칸에 기록됩니다. 하역 경로에서는 "그 칸에 차가 있는가"만 보고, 적어 낸 수요 번호가 그 칸의 차와 같은지는 비교하지 않습니다. 대신 항구를 떠날 때 배에 있는 차의 수요별 대수를 셉니다. 이 사실은 7장에서 다시 나옵니다.
  • 임시로 내린 차를 다시 실을 때는 원래의 수요 번호로 싣습니다. 그래야 항구를 떠날 때의 대수 검사를 통과합니다.
4부 · 비용과 목적함수

경로 하나의 비용 = 고정비 + 간선 수

경로 비용 = F + (경로가 지난 간선의 수)

경로 [0, 1, 2, 3]은 간선 3개를 지나므로 F = 10일 때 비용이 13입니다. 고정비 F는 경로 하나에 한 번 붙습니다. 그래서 임시 하역 후 재적재는 경로가 둘이라 고정비도 두 번 냅니다. 문제 설명에 실린 실제 문제 파일에서는 F = 100입니다. F가 이렇게 크면 경로의 개수를 줄이는 것이 길이를 줄이는 것보다 훨씬 중요합니다.

차 한 대는 아무리 잘해도 선적 한 번, 하역 한 번, 즉 경로 두 개가 필요합니다. 따라서 줄일 수 있는 것은 두 가지뿐입니다.

  • 재배치 경로의 개수와 길이.
  • 선적·하역 경로의 길이. 출입구에서 가까운 칸을 쓸수록, 그리고 돌아가지 않을수록 짧습니다.

목적함수 = 총비용 − LB

점수로 쓰는 값은 총비용 그 자체가 아니라 총비용에서 하한값 LB를 뺀 값입니다. LB는 "차들이 서로 길을 막지 않는다고 치면 최소 얼마가 드는가"입니다. 문제 설명의 정의는 다음과 같습니다.

LB = Σp [ F × (Loadp + Unloadp) + (가까운 칸 Loadp개의 거리 합) + (가까운 칸 Unloadp개의 거리 합) ]
  • Loadp: 항구 p에서 실어야 하는 차의 수(출발 항구가 p인 수요의 합).
  • Unloadp: 항구 p에서 내려야 하는 차의 수(도착 항구가 p인 수요의 합).
  • 거리: 출입구에서 그 노드까지의 최단 거리(간선 수).

항구마다 "실을 차는 출입구에서 가장 가까운 칸들에 싣고, 내릴 차도 가장 가까운 칸들에 있었다"고 낙관적으로 가정한 값입니다. 재배치는 0번이라고 가정합니다. 이 계산은 항구마다 배가 비어 있는 것처럼 셉니다. 가까운 칸에 이미 다른 차가 서 있는지, 같은 차가 싣는 칸과 내리는 칸이 같은지는 따지지 않습니다. 그래서 실제로는 이 값을 달성할 수 없는 경우가 대부분입니다.

예시에서 계산해 봅시다. 노드 1, 2, 3, 4의 거리는 1, 2, 3, 4입니다.

목적함수 = (모든 경로 비용의 합) − LB

LB는 문제마다 정해진 상수이므로, 목적함수를 최소화하는 것과 총비용을 최소화하는 것은 같은 일입니다. LB를 빼는 이유는 "피할 수 없는 기본 비용"을 걷어 내고 막힘 때문에 추가로 든 비용만 비교하기 위해서입니다. 목적함수가 0이면 아무도 서로를 막지 않은 완벽한 해입니다.

문제 크기결선 평가 문제는 노드 400개 이하라고 공지되었습니다.

순위는 「나보다 잘한 팀 수」로 매긴다

문제마다 점수를 매겨 합산합니다. R을 평가 대상 팀 수, nb를 그 문제에서 나보다 더 좋은(작은) 목적함수를 낸 팀 수라고 하면

점수 = max(0, R − nb)해가 유효할 때
점수 = −1무효해, 시간 초과, 실행 오류일 때

이 방식에는 두 가지 성질이 있습니다. 첫째, 목적함수 값의 차이의 크기는 상관없고 순서만 중요합니다. 1만큼 이기나 1000만큼 이기나 점수는 같습니다. 둘째, 무효해는 꼴찌보다 나쁩니다. 그래서 어떤 문제가 와도 유효해를 내는 안정성이 중요합니다.

결선은 본선에 마지막으로 제출한 알고리즘을 그대로 숨겨진 문제 14개에 돌려 평가했습니다. 최종 순위는 이 문제 풀이 점수(대회에서는 순위표를 리더보드라고 부릅니다)를 80점 만점으로, 발표 평가를 20점 만점으로 환산해 더한 값으로 정했습니다.

6부 · 문제의 성격

왜 어려운가

  • 결정이 세 겹입니다. 어느 칸에 세울지(배치), 어떤 경로로 갈지(경로), 어떤 순서로 실행할지(순서)를 함께 정해야 하고 셋이 서로 얽혀 있습니다.
  • 항구 사이가 이어져 있습니다. 항구 0에서 차를 어디에 세웠느냐가 항구 3에서의 재배치 비용을 결정합니다. 항구별로 따로 풀 수 없습니다.
  • 빈칸이 넉넉하지 않습니다. 수요는 어느 시점에도 배의 칸 수를 넘지 않게, 그리고 미리 정한 비율만큼 배를 채우도록 무작위로 생성됩니다(대회 사이트 「문제 생성 방법」의 설명. 그 비율을 정하는 값의 이름이 total_allocation_ratio이고, 문제별 값은 공개된 설명에 없습니다). 예시처럼 어떤 구간에서 배가 꽉 차면 위치변경할 빈칸조차 없습니다.
  • 고정비가 큽니다. 재배치 한 번이 선적·하역 길이를 수십 칸 줄이는 것보다 비쌉니다. 재배치 횟수가 한 번만 달라져도 순위가 갈립니다.

CVRPTW와 견주어 보면

차량 경로 문제(CVRPTW)에 익숙한 독자를 위해 닮은 점과 다른 점을 적어 둡니다.

CVRPTW이 문제
정하는 것고객을 어느 차량에, 어떤 순서로차를 어느 칸에, 어느 항구에서 임시로 내릴지, 어떤 순서·경로로
「경로」의 뜻차량 한 대의 하루 방문 순서차 한 대가 배 안에서 한 번 움직이는 길(짧고, 수가 많음)
용량차량 적재량노드당 한 대
시간시간창없음. 대신 항구 순서와 「막힘」이 선후 관계를 만듭니다
가장 닮은 변형LIFO 적재 조건이 붙은 집화·배송 문제(PDP with LIFO loading). 나중에 실은 짐을 먼저 내려야 하는 제약입니다. 이 문제의 배 (나)는 정확히 스택이고, 일반 deck graph는 "그래프 모양의 스택"입니다.
흔한 풀이구성 휴리스틱 + 지역 탐색 + 메타휴리스틱1등 팀은 정수계획 모형 + 솔버(다른 팀의 풀이는 이 문서에서 다루지 않습니다)

마지막 줄이 이 문서의 주제입니다. 다음 장에서 1등 팀이 문제를 어떻게 바라봤는지를 수식 없이 먼저 봅니다.

이해 확인

예시에서 수요 번호 3은 어떤 차인가요?

K의 네 번째 항목 [[1, 3], 1]입니다. 항구 1에서 실어 항구 3에서 내릴 차 1대입니다. 수요 번호는 K 목록의 순번(0부터)입니다.

경로 [0, 1, 2]를 실행하려는데 노드 2에 이미 차가 있습니다. 유효한가요?

무효입니다. 선적 경로는 마지막 노드를 포함해 경로 위의 모든 노드가 비어 있어야 합니다.

임시 하역 후 재적재 한 번의 비용은 최소 얼마인가요?

경로가 둘이므로 고정비 2F, 각 경로의 길이가 최소 1이므로 최소 2F + 2입니다. 위치변경은 경로 하나라 최소 F + 1입니다.

목적함수가 음수가 될 수 있나요?

없습니다. LB는 어떤 유효해의 총비용보다도 작거나 같게 정의되어 있습니다. 차마다 선적·하역 경로가 하나씩은 필요하고, 그 길이는 가장 가까운 칸들을 썼을 때보다 짧을 수 없기 때문입니다.

어떤 팀이 한 문제에서 2등보다 목적함수가 절반인 해를 냈습니다. 점수를 더 받나요?

아니요. 점수는 "나보다 잘한 팀 수"만으로 정해지므로 근소하게 이겨도 같은 점수입니다.
