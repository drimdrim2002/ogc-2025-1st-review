MIP 기초 ①: 문제를 수식으로 적는 법

이 장의 목표는 하나입니다. Σ와 ∀가 섞인 식 한 줄을 보고 "아, 이건 이런 조건이구나" 하고 한국어 문장으로 읽을 수 있게 되는 것, 그리고 간단한 조건을 반대로 식으로 적을 수 있게 되는 것입니다.

솔버가 그 식을 어떻게 푸는지는 다음 장에서 다룹니다. 이 장에서는 솔버를 "식을 넣으면 답이 나오는 상자"로만 생각해도 됩니다. 이 문제(RORO)의 식은 6장에서 나오고, 여기서는 트럭, 배낭, 배정, 그리고 CVRPTW처럼 익숙한 소재만 씁니다.

1부 · 모형의 세 요소

결정변수, 제약식, 목적함수

발표자료 2쪽은 최적화 모형으로 의사결정을 하는 과정을 네 단계로 적고 있습니다. 앞의 세 단계가 모형을 적는 일이고, 네 번째가 솔버의 일입니다.

단계이름하는 일
1결정변수내가 정할 수 있는 것을 숫자 변수로 둡니다. "큰 트럭을 몇 대 부를까" → x.
2제약식변수들이 지켜야 하는 조건을 등식·부등식으로 적습니다. "실어야 할 짐은 다 실어야 한다".
3목적함수좋고 나쁨을 재는 식 하나를 적고, 최소화 또는 최대화한다고 선언합니다. "총비용".
4풀이솔버가 제약을 모두 지키는 변수 값 중에서 목적함수가 가장 좋은 것을 찾습니다.

용어 몇 개를 먼저 정해 둡니다.

  • 파라미터(데이터): 문제에서 주어진 숫자. 트럭 용량, 고정비 F, 수요량처럼 내가 못 바꾸는 값입니다. 식에서 문자로 쓰여도 변수가 아닙니다.
  • 가능해(feasible solution): 모든 제약을 지키는 변수 값 한 벌. 좋은지 나쁜지는 따지지 않습니다. 1장에서 대회 용어로 「유효해」라고 부른 것과 같은 개념입니다.
  • 최적해(optimal solution): 가능해 중 목적함수 값이 가장 좋은 것.
  • 불능(infeasible): 제약을 다 지키는 값이 아예 없는 경우. 변수 값 한 벌이 제약을 어길 때도 "그 값은 불능"이라고 합니다(1장의 「무효」).

첫 예: 트럭 부르기

짐 30톤을 보내야 합니다. 큰 트럭은 9톤을 싣고 한 대에 10만 원, 작은 트럭은 5톤을 싣고 7만 원입니다. 가장 싸게 보내려면 각각 몇 대를 불러야 할까요?

변수   x = 큰 트럭 대수,  y = 작은 트럭 대수
최소화  10x + 7y총비용(만 원)
제약   9x + 5y ≥ 30짐을 다 실을 수 있어야 한다
        x ≥ 0, y ≥ 0, x와 y는 정수트럭은 반 대를 부를 수 없다

이것이 모형의 전부입니다. "어떻게 찾을지"는 한 줄도 없고 "무엇이 좋은 답인지"만 적혀 있습니다. 답은 큰 트럭 3대와 작은 트럭 1대(37만 원)인데, 이 답이 어떻게 나오는지는 4장에서 이 예로 직접 따라가 봅니다.

LP, IP, MIP: 무엇이 허용되는가

아무 식이나 적을 수 있는 것은 아닙니다. 범용 솔버가 받는 형식은 정해져 있습니다.

이름변수식의 모양풀기
LP 선형계획모두 실수목적함수와 제약식이 모두 1차식.
(상수 × 변수)들의 합과 상수의 비교(≤, ≥, =)만 허용		쉽다. 변수 수백만 개도 풉니다.
IP 정수계획모두 정수어렵다(NP-hard).
MIP 혼합정수계획일부는 정수, 일부는 실수어렵다. IP를 포함하는 일반형입니다.

값이 0 아니면 1인 정수 변수를 이진변수(binary variable)라고 합니다. "한다/안 한다"를 나타내는 스위치이고, 조합최적화 모형의 주재료입니다. MILP, ILP처럼 Linear를 넣어 부르기도 하는데 같은 것입니다. 발표자료가 쓰는 「정수선형최적화」도 같은 말입니다.

1차식만 된다는 제한이 처음에는 답답합니다. 다음은 그대로는 적을 수 없는 것들입니다.

  • 변수끼리의 곱: x·y
  • 조건문: "x가 1이면 이 제약을 적용"
  • max, min, 절댓값, 나눗셈
  • "같지 않다"(≠), 진부등호(<, >). 솔버는 경계를 포함하는 ≤, ≥만 받습니다. 정수 변수라면 x < 5를 x ≤ 4로 바꿔 적으면 됩니다.

이런 것들을 이진변수와 1차 부등식으로 우회해서 표현하는 정해진 요령들이 있습니다. 3부에서 다룹니다. MIP 모형을 읽고 쓰는 실력의 대부분은 이 요령들을 얼마나 알고 있느냐입니다.

2부 · 기호 읽는 법

첨자, Σ, ∀

실제 모형은 변수가 수천, 수만 개라서 하나씩 이름을 붙일 수 없습니다. 그래서 첨자(인덱스)를 씁니다. 배낭 문제로 봅니다. 물건이 n개 있고 물건 j의 가치는 vj, 무게는 wj, 배낭 용량은 W입니다.

변수   xj ∈ {0, 1}∀ j = 1, …, n   (물건 j를 넣으면 1)
최대화  Σj=1..n vj xj넣은 물건의 가치 합
제약   Σj=1..n wj xj ≤ W넣은 물건의 무게 합이 용량 이하
  • xj는 변수 하나가 아니라 변수 n개(x1, …, xn)를 한꺼번에 부르는 이름입니다.
  • xj ∈ {0, 1}은 "xj는 0 또는 1만 가질 수 있다", 곧 이진변수라는 선언입니다.
  • Σj=1..n는 for 루프로 더하라는 뜻입니다. sum(v[j]*x[j] for j in range(n)). 범위가 뻔할 때는 Σj처럼 줄여 씁니다. Σ가 둘 이어진 Σi Σk는 이중 for 루프, 곧 모든 (i, k) 조합에 대한 합입니다.
  • ∀("모든 ~에 대해")는 그 줄을 첨자 값마다 하나씩 복사해서 여러 줄로 만들라는 뜻입니다. 역시 for 루프입니다.
  • xj에 곱해진 vj와 wj는 파라미터입니다. 변수 × 파라미터이므로 1차식입니다.

xj가 1이면 wj가 합에 들어가고 0이면 빠집니다. 이진변수에 숫자를 곱해서 더하면 "고른 것들의 합"이 됩니다. 이 패턴은 어디에나 나옵니다.

Σ와 ∀를 구별하는 연습: 배정 문제

고객 i를 차량 k에 배정하는 문제를 봅니다(순서는 정하지 않고 누구 담당인지만). 고객 i의 물량은 qi, 차량 용량은 Q, 고객 i를 차량 k에 맡길 때의 비용은 cik입니다.

변수   xik ∈ {0, 1}∀ 고객 i, ∀ 차량 k   (i를 k에 맡기면 1)
최소화  Σi Σk cik xik
(1)  Σk xik = 1∀ 고객 i
(2)  Σi qi xik ≤ Q∀ 차량 k

식 (1)을 읽는 요령은 ∀ 쪽 첨자를 하나로 고정하고 Σ 쪽을 풀어 쓰는 것입니다. 고객이 3번, 차량이 A·B·C라면

x3A + x3B + x3C = 1

셋 중 정확히 하나만 1입니다. "고객 3은 정확히 한 차량에 배정된다." 이 줄이 고객 수만큼 있습니다. 식 (2)는 반대로 차량을 고정하고 고객 쪽으로 더합니다. "차량 A에 배정된 고객들의 물량 합이 용량 이하." 이 줄이 차량 수만큼 있습니다.

같은 변수 xik를 표로 그리면, (1)은 가로줄 합에 대한 조건이고 (2)는 세로줄 합에 대한 조건입니다. 어느 첨자를 더하고 어느 첨자를 남기느냐가 식의 뜻을 결정합니다.

식을 읽는 세 단계. ① 첨자가 무엇을 가리키고 범위가 어디까지인지 확인합니다. ② 변수 하나의 뜻을 한국어 문장으로 말해 봅니다("xik = 1은 고객 i를 차량 k가 맡는다는 뜻"). ③ ∀ 쪽 첨자에 구체적인 값을 넣고 Σ를 풀어 써서 그 한 줄이 무슨 조건인지 봅니다. 6장에서 tryAgain의 식을 읽을 때도 이 순서로 읽습니다.

크기도 여기서 셉니다. 고객 100명, 차량 10대면 변수는 100 × 10 = 1,000개, 제약은 100 + 10 = 110개입니다. 변수의 수는 첨자 범위의 곱, 제약의 수는 ∀ 범위의 곱입니다.

3부 · 모델링 관용구

이진변수로 논리를 적는 법

이진변수 x, y가 있을 때 "x이면 y", "둘 다는 안 됨" 같은 논리를 1차 부등식으로 적는 방법입니다. 표의 식이 왜 그 뜻이 되는지는 x와 y에 0과 1을 넣어 보면 바로 확인됩니다.

하고 싶은 말식확인
x이면 y
(x를 하려면 y가 켜져 있어야)		x ≤ yx=1이면 y ≥ 1이어야 하므로 y=1. x=0이면 y는 자유.
x와 y를 둘 다 할 수는 없다x + y ≤ 1둘 다 1이면 2 ≤ 1이 되어 위반.
y가 켜져 있으면 x는 못 한다x ≤ 1 − y위와 같은 식을 옮겨 적은 것. y=1이면 x ≤ 0.
여럿 중 많아야 하나x1 + x2 + x3 ≤ 1둘 이상이 1이면 위반.
여럿 중 정확히 하나x1 + x2 + x3 = 1배정 문제의 식 (1).
y이면 x1, x2, x3 중 적어도 하나y ≤ x1 + x2 + x3y=1인데 오른쪽이 모두 0이면 1 ≤ 0으로 위반.

두 개를 한 줄로 합치는 것도 자주 씁니다. 이 문서의 뒤에서 그대로 만나게 될 모양이라 미리 봐 둡니다.

식뜻 (두 가지를 동시에)
x1 + x2 + x3 ≤ y① x들 중 많아야 하나만 1이다(y가 최대 1이므로). ② 그 하나가 1이려면 y가 1이어야 한다.
x1 + x2 + x3 ≤ 1 − y① x들 중 많아야 하나만 1이다. ② y가 1이면 x는 전부 0이다. 뒤집어 읽으면, x 중 하나라도 1이면 y는 0이다.

주의할 점이 하나 있습니다. x ≤ y는 "x이면 y"일 뿐 "y이면 x"가 아닙니다. y=1, x=0도 허용됩니다. 한쪽 방향만 강제하는 식인지 양쪽인지 구별해서 읽어야 합니다. 반대 방향은 대개 적을 필요가 없습니다. 예를 들어 y가 "창고를 연다"(여는 데 100만 원), x가 "그 창고에서 물건을 보낸다"라면, x ≤ y만 적어도 됩니다. 보내지도 않을 창고를 여는 해(y = 1, x = 0)는 식으로는 허용되지만 100만 원이 더 드니, 비용을 최소화하는 솔버가 고르지 않습니다. y에 비용이 없는 경우에는 y = 1, x = 0인 해가 답에 섞여 나올 수 있고, 그래도 해롭지 않으면 그대로 둡니다. 6장의 모형에 그런 변수가 있습니다.

big-M: 스위치로 제약을 켜고 끄기

"이진변수 y가 1일 때만 이 제약을 적용하고 싶다"는 조건문은 그대로 적을 수 없습니다. 대신 아주 큰 상수 M을 써서, 스위치가 꺼졌을 때는 제약이 있으나 마나 하게 만듭니다. 이것을 big-M 기법이라고 합니다.

고정비 (쓰려면 먼저 열어야 한다)

창고에서 내보내는 양 x(실수)와 창고를 여는지 여부 y(이진)가 있습니다. 창고를 열어야만 내보낼 수 있습니다.

x ≤ M · y

y = 0이면 x ≤ 0이라 못 내보내고, y = 1이면 x ≤ M이라 사실상 제한이 없습니다. M은 x가 가질 수 있는 최댓값 이상이면 됩니다(창고 용량 같은 값).

조건부 부등식 (CVRPTW의 시간창)

CVRPTW를 MIP로 적을 때 꼭 나오는 식입니다. xij는 "고객 i 다음에 바로 j를 방문하면 1"인 이진변수, ti는 고객 i의 서비스 시작 시각(실수 변수), si는 서비스 시간, τij는 이동 시간입니다.

tj ≥ ti + si + τij − M (1 − xij)∀ i, j
  • xij = 1이면 마지막 항이 0이 되어 tj ≥ ti + si + τij. "j의 시작은 i를 마치고 이동한 뒤."
  • xij = 0이면 오른쪽이 아주 큰 음수가 되어 항상 성립. 아무 조건도 아닙니다.

big-M은 편하지만 대가가 있습니다. M이 클수록 솔버가 풀기 어려워집니다. 이런 모형을 「약하다」고 말합니다. 약하다는 것은 틀렸다는 뜻이 아니라, 솔버가 탐색 중에 쓰는 어림 계산이 실제 답과 멀어져 헛걸음이 많아진다는 뜻입니다. 정확한 뜻은 4장 4부에서 설명합니다. 지금은 "big-M 없이 적을 수 있으면 그쪽이 좋다"만 기억해 두면 됩니다. M을 써야 한다면 식이 성립하는 한도에서 가장 작은 값을 고릅니다. tryAgain의 모형에는 big-M이 하나도 없습니다.

그 밖의 우회법: 같지 않다, 곱, 절댓값, 최댓값

앞에서 "그대로는 적을 수 없다"고 한 것들의 대표적인 우회법입니다. 이 문서의 뒤에서는 쓰이지 않으니 한 번 훑어보고 넘어가도 됩니다. 요점은 보조 변수를 하나 더 두고 부등식 몇 줄로 묶는다는 것입니다.

하고 싶은 말식왜 되는가
이진변수 x와 y가 달라야 한다x + y = 1하나는 0, 하나는 1일 때만 성립.
이진변수의 곱 w = x·y
("x와 y를 둘 다 하면 w")		w ≤ x, w ≤ y,
w ≥ x + y − 1		앞의 두 줄은 "둘 중 하나라도 0이면 w = 0", 셋째 줄은 "둘 다 1이면 w ≥ 1".
절댓값 |a − b|를 최소화새 변수 t를 두고
t ≥ a − b, t ≥ b − a,
목적함수에 t		t는 두 값 중 큰 쪽 이상이어야 하고, 최소화하므로 딱 그 값까지 내려옵니다.
여러 값 중 최댓값을 최소화
(가장 늦게 끝나는 차량의 종료 시각 등)		새 변수 t를 두고
모든 k에 대해 t ≥ Tk,
목적함수에 t		절댓값과 같은 원리.
정수 변수 a, b가 달라야 한다이진변수 s를 두고
a ≥ b + 1 − M·s,
b ≥ a + 1 − M·(1 − s)		s = 0이면 a > b, s = 1이면 b > a. 둘 중 하나를 고르게 하는 big-M 택일 제약입니다.

절댓값과 최댓값의 요령은 "최소화하는 방향"일 때만 통합니다. 반대로 절댓값을 크게 하고 싶을 때는 이진변수가 필요합니다. 이런 세부는 필요할 때 10장의 참고자료(관용구 모음집)에서 찾아보면 됩니다.

수량 보존: 들어온 만큼 나간다

네트워크나 재고처럼 "양"이 흐르는 문제에서는 지점마다 보존식을 적습니다.

(들어오는 양의 합) − (나가는 양의 합) = (그 지점에서 소비되는 양)

숫자로 보면 이렇습니다. 어떤 물류 거점에 두 곳에서 3톤과 2톤이 들어오고, 그 거점에서 1톤을 소비한다면, 나가는 양은 4톤이어야 합니다. (3 + 2) − 4 = 1. 들어오는 양과 나가는 양이 변수이면 이 등식이 제약식이 됩니다.

fA→거점 + fB→거점 − f거점→C = 1f는 구간별 운송량 변수

CVRP에서는 "고객 노드에 들어온 차량은 반드시 나간다"가 이 꼴입니다. 변수가 이진이든 정수든 실수든 모양은 같습니다. 식을 읽을 때는 더해지는 항(+)과 빼지는 항(−)을 각각 "들어오는 것", "나가는 것"으로 나눠 보면 됩니다. 6장의 수요 제약이 이 꼴입니다.

4부 · 익숙한 문제에 대 보기

CVRPTW를 MIP로 적으면

관용구들이 한 모형 안에서 어떻게 모이는지를 익숙한 문제로 봅니다. 교과서에 나오는 「3첨자 정식화」를 간추린 것입니다(책마다 세부는 조금씩 다릅니다). 먼저 기호입니다.

기호종류뜻
i, j, h첨자노드. 0은 차고지, 나머지는 고객
k첨자차량
cij, τij파라미터i에서 j로 가는 비용, 이동 시간
qi, si파라미터고객 i의 물량, 서비스 시간
ai, bi파라미터고객 i의 시간창. 서비스는 ai 이후, bi 이전에 시작해야 함
Q파라미터차량 용량
xijk이진변수차량 k가 i 다음에 바로 j로 가면 1
tik실수 변수차량 k가 i에서 서비스를 시작하는 시각
최소화  Σk Σi Σj cij xijk총 이동 비용
(1)  Σk Σj xijk = 1∀ 고객 i   정확히 한 번, 한 차량이 방문
(2)  Σi xihk − Σj xhjk = 0∀ 고객 h, ∀ k   들어오면 나간다
(3)  Σj x0jk ≤ 1∀ k   차고지에서 많아야 한 번 출발
(4)  Σi qi Σj xijk ≤ Q∀ k   용량
(5)  tjk ≥ tik + si + τij − Mij (1 − xijk)∀ 고객 i, j, ∀ k   시각의 선후
(6)  ai ≤ tik ≤ bi∀ 고객 i, ∀ k   시간창

관용구로 분해하면 (1)은 "정확히 하나", (2)는 수량 보존, (3)은 "많아야 하나", (4)는 "고른 것들의 합", (5)는 big-M 조건부 부등식입니다. 새로운 것은 없습니다. (4)의 안쪽 합 Σj xijk는 "차량 k가 고객 i를 방문하면 1"이 되는 값입니다.

(5)의 M은 "xijk = 0일 때 식이 항상 성립할 만큼"만 크면 됩니다. tik는 많아야 bi이고 tjk는 적어도 aj이므로, Mij = bi + si + τij − aj로 잡으면 충분합니다. 시간창이 넓을수록 M이 커집니다.

이 모형에서 두 가지를 눈여겨봐야 합니다.

  • 변수의 수. 고객 100명, 차량 10대면 x가 약 100 × 100 × 10 = 10만 개입니다. "누가 누구 다음인가"라는 순서를 변수로 만들면 고객 수의 제곱으로 불어납니다.
  • 식 (5)의 big-M. 순서와 시각을 잇는 데 big-M이 들어갑니다. 이 때문에 이 모형은 솔버가 풀기 어려운 것으로 알려져 있고, 고객 수가 조금만 커져도 그대로는 잘 풀리지 않습니다.

순서를 적을 때 따라오는 골칫거리: 부분 순환

식 (5)는 시간창만 지키는 것이 아니라 숨은 일을 하나 더 합니다. 그것을 보려고 시간창이 없는 가장 단순한 경로 문제, 외판원 문제(TSP)를 봅니다. 도시 n개를 한 번씩 들르고 돌아오는 가장 짧은 순환을 찾습니다. xij가 "i 다음에 j"이면, 가장 먼저 떠오르는 식은 이렇습니다.

Σj xij = 1∀ i   모든 도시에서 정확히 한 번 나간다
Σi xij = 1∀ j   모든 도시로 정확히 한 번 들어온다

이것만으로는 틀립니다. 도시가 여섯 개일 때 1 → 2 → 3 → 1과 4 → 5 → 6 → 4, 이렇게 따로 노는 순환 두 개도 두 식을 모두 지킵니다. 이런 것을 부분 순환(subtour)이라고 합니다. 식은 "각 도시의 앞뒤"라는 이웃 관계만 보기 때문에, 전체가 하나로 이어져 있는지는 알지 못합니다.

가장 간단한 처방은 도시마다 "몇 번째로 방문하는가"를 나타내는 변수 ui를 추가하고, 이어진 도시끼리는 순번이 늘어나도록 강제하는 것입니다. 제안자들의 이름을 따서 MTZ(Miller–Tucker–Zemlin) 제약이라고 합니다.

uj ≥ ui + 1 − (n − 1)(1 − xij)∀ 출발 도시가 아닌 i, j
1 ≤ ui ≤ n − 1∀ 출발 도시가 아닌 i

앞에서 본 big-M 조건부 부등식 그대로입니다(M = n − 1). xij = 1이면 uj ≥ ui + 1. 출발 도시를 지나지 않는 순환 4 → 5 → 6 → 4가 있다면 u5 > u4, u6 > u5, u4 > u6이 되어 모순이므로, 그런 순환은 불능이 됩니다. CVRPTW의 식 (5)도 같은 일을 합니다. 경로를 따라 시각 t가 계속 늘어나야 하므로 차고지를 거치지 않는 순환은 생길 수 없습니다.

여기서 기억할 것은 두 가지입니다.

  • "전체가 하나로 이어져 있다"는 조건은 이웃만 보는 식으로는 적기 어렵습니다. 순번 변수 같은 장치가 추가로 필요하고, 거기에 대개 big-M이 따라옵니다.
  • 순서를 변수로 적으면 모형이 크고 약해집니다. 그래서 CVRPTW는 큰 문제에서 휴리스틱이 널리 쓰입니다.

2장에서 본 tryAgain의 핵심 생각, "순서를 정하지 않아도 되게 문제를 좁힌다"가 왜 값진지가 여기서 나옵니다. 순서 변수를 없앨 수 있으면 MIP가 휴리스틱과 겨룰 만해집니다. 그리고 5장에서, RORO 문제에도 부분 순환과 똑같은 종류의 골칫거리가 있고 tryAgain이 그것을 순번 변수 없이 처리했다는 것을 보게 됩니다.

코드로 적어 보기

트럭 예를 두 가지 도구로 적으면 다음과 같습니다. 모형의 세 요소가 코드 줄에 일대일로 대응합니다.

gurobipy

import gurobipy as gp
from gurobipy import GRB

m = gp.Model("trucks")
x = m.addVar(vtype=GRB.INTEGER, lb=0, name="big")      # 결정변수
y = m.addVar(vtype=GRB.INTEGER, lb=0, name="small")
m.setObjective(10 * x + 7 * y, GRB.MINIMIZE)           # 목적함수
m.addConstr(9 * x + 5 * y >= 30, name="load")          # 제약식
m.optimize()                                           # 풀이
print(x.X, y.X, m.ObjVal)                              # 변수 값은 .X, 목적함수 값은 .ObjVal

OR-Tools (무료 솔버 SCIP 사용)

from ortools.linear_solver import pywraplp

s = pywraplp.Solver.CreateSolver("SCIP")
x = s.IntVar(0, s.infinity(), "big")
y = s.IntVar(0, s.infinity(), "small")
s.Minimize(10 * x + 7 * y)
s.Add(9 * x + 5 * y >= 30)
s.Solve()
print(x.solution_value(), y.solution_value(), s.Objective().Value())

첨자가 붙은 변수는 dict나 배열에 담고, Σ와 ∀는 for 루프로 씁니다. 배정 문제의 식 (1)은 gurobipy로 이렇게 됩니다. customers와 vehicles는 고객 번호와 차량 번호의 목록(예: range(20), range(3))이고, gp.quicksum은 변수가 든 식을 더하는 gurobipy의 합계 함수로 Σ에 해당합니다.

x = {(i, k): m.addVar(vtype=GRB.BINARY) for i in customers for k in vehicles}
for i in customers:                                        # ∀ 고객 i
    m.addConstr(gp.quicksum(x[i, k] for k in vehicles) == 1)   # Σ_k x_ik = 1

tryAgain의 C++ 코드도 정확히 이 구조입니다. 바깥 for 루프가 ∀, 안쪽 for 루프로 식을 쌓는 부분이 Σ입니다. 실제 코드는 6장에서 제약식마다 발췌해 보입니다.

위 코드는 이 문서를 작성한 환경에 솔버가 설치되어 있지 않아 직접 실행해 확인하지는 못했습니다. 두 라이브러리의 기본 사용법 그대로이므로, pip install gurobipy 또는 pip install ortools 후 실행하면 x = 3, y = 1, 목적함수 37이 나와야 합니다. pip으로 설치한 gurobipy에는 변수 2,000개·제약 2,000개까지 풀 수 있는 제한 라이선스가 들어 있어서, 이 문서의 예제들은 별도 라이선스 없이 돌릴 수 있습니다.

이해 확인

이진변수 a, b, c가 있습니다. "a를 하면 b와 c 중 적어도 하나는 해야 한다"를 식으로 적어 보세요.

a ≤ b + c. a = 1인데 b = c = 0이면 1 ≤ 0이 되어 위반됩니다.

x1 + x2 ≤ 1 − y에서 y = 0이면 무슨 조건이 남나요?

x1 + x2 ≤ 1. 둘 중 많아야 하나입니다. y = 1이면 둘 다 0이어야 합니다.

배정 문제에서 고객 50명, 차량 4대일 때 변수와 제약은 각각 몇 개인가요?

변수 xik는 50 × 4 = 200개. 제약은 식 (1)이 50개, 식 (2)가 4개로 54개입니다.

"x와 y가 달라야 한다(x ≠ y)"는 왜 그대로 못 적나요?

1차식의 ≤, ≥, =만 허용되기 때문입니다. 3부의 "그 밖의 우회법" 표에 있듯이, 이진변수라면 x + y = 1로 적을 수 있고(하나는 0, 하나는 1), 일반 정수라면 보조 이진변수와 big-M 택일 제약이 필요합니다.

big-M 식 tj ≥ ti + si + τij − M(1 − xij)에서 M을 너무 작게 잡으면 어떤 일이 생기나요?

xij = 0일 때도 제약이 살아 있게 됩니다. i와 j가 이어져 있지 않은데도 tj가 ti보다 어느 정도 뒤여야 한다는 엉뚱한 조건이 생겨, 멀쩡한 해가 잘려 나갑니다. M은 "스위치가 꺼졌을 때 식이 항상 성립할 만큼"은 커야 합니다.
