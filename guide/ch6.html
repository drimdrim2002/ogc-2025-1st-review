정식화 한 줄씩: 변수 x, y, z와 제약식 여섯 가지

이 장은 tryAgain의 모형 전체를 수식 한 줄, 코드 한 덩어리, 예시의 숫자 하나씩 짝지어 읽습니다. 새로운 생각은 없습니다. 5장의 「구간」, 「머무는 차」, 「접근 가능」을 3장의 관용구로 옮겨 적은 것이 전부입니다.

수식은 발표자료 부록(13~15쪽)에 있고 코드는 function.cpp의 formulate(43~177줄)입니다. 둘을 대조한 결과 수식 자체는 일치했습니다. 설명이 다른 부분은 장 끝의 대조표에 모았습니다.

첨자의 약속은 이렇습니다. p, q, r은 항구, i, j는 노드입니다. 변수의 첨자에 항구가 둘 이상 나올 때는 왼쪽 것이 항상 더 이른 항구입니다. xpqi에서 p < q이고, z의 세 첨자는 차례로 (실은 항구, 쪼갠 항구, 내릴 항구)여서 왼쪽에서 오른쪽으로 커집니다. 뒤의 식에서 zprq나 zrpq처럼 글자의 자리가 바뀌어 나오는데, 그때는 r이 가운데 자리(p < r < q) 또는 맨 앞 자리(r < p < q)에 있다는 뜻입니다.

변수마다 짚어 둘 점이 있습니다.

  • x는 차가 아니라 구간을 가리킵니다. 5장에서 본 대로, 임시 하역을 당한 차 한 대는 구간 두 개가 되고 x 두 개가 1이 됩니다. xpqi에는 "어느 수요의 차인지"가 들어 있지 않습니다. 같은 p, q를 가진 구간은 서로 구별하지 않습니다.
  • x가 배치의 전부입니다. xpqi = 1이면 "항구 p를 떠날 때부터 항구 q에 닿을 때까지 칸 i에 차가 있다"는 것이 정해집니다. 모든 항구에서의 배 상태가 x만으로 결정됩니다.
  • y는 첫 항구와 마지막 항구에는 없습니다. 항구 0에서는 배가 비어 있고 항구 P−1에서는 전부 내리므로 머무는 차가 없습니다. 모든 칸이 접근 가능하니 변수로 둘 필요가 없습니다.
  • z는 "누가" 아니라 "몇 대"입니다. 같은 수요의 차는 구별하지 않으므로 대수만 세면 됩니다.

코드에서 변수는 종류마다 1차원 배열 하나에 담기고, Base.hpp의 idx2, idx3가 첨자 둘 또는 셋을 배열 위치로 바꿉니다. 2차원, 3차원 배열을 한 줄로 펴서 쓰는 흔한 방법입니다. PortId와 NodeId는 int의 다른 이름입니다.

// Base.hpp
inline const int idx2(const int i, const int j, const int n) { return i * n + j; }
inline const int idx3(const int i, const int j, const int k, const int n, const int m)
{ return i * n * m + j * m + k; }

// 변수를 담을 배열 (myalgorithm.cpp). GRBVar는 Gurobi의 변수 하나를 가리키는 객체
vector<GRBVar> x_pqi(num_ports * num_ports * num_nodes);
vector<GRBVar> y_pi(num_ports * num_nodes);
vector<GRBVar> z_pqr(num_ports * num_ports * num_ports);

// x_pqi 만들기 (function.cpp 47~56줄)
for (PortId p = 0; p < num_ports - 1; ++p)
    for (PortId q = p + 1; q < num_ports; ++q)
        for (NodeId i = 1; i < num_nodes; ++i)   // 출입구(0)는 제외
            x_pqi[idx3(p, q, i, num_ports, num_nodes)] =
                model.addVar(0.0, 1.0, 0.0, GRB_BINARY,
                             "x_" + to_string(p) + "_" + to_string(q) + "_" + to_string(i));

// y_pi 만들기 (58~66줄). 첫 항구(0)와 마지막 항구(P−1)는 건너뛴다
for (PortId p = 1; p < num_ports - 1; ++p)
{
    for (NodeId i = 0; i < num_nodes; ++i)
        y_pi[idx2(p, i, num_nodes)] = model.addVar(0.0, 1.0, 0.0, GRB_BINARY, "y_" + ...);
    model.addConstr(y_pi[idx2(p, 0, num_nodes)] == 1.0);   // 출입구는 항상 접근 가능 (뒤의 제약 ⑥)
}

// z_pqr 만들기 (68~78줄)
for (PortId p = 0; p < num_ports - 2; ++p)
    for (PortId q = p + 1; q < num_ports - 1; ++q)
        for (PortId r = q + 1; r < num_ports; ++r)
            z_pqr[idx3(p, q, r, num_ports, num_ports)] =
                model.addVar(0.0, GRB_INFINITY, 0.0, GRB_INTEGER, "z_" + ...);

addVar(하한, 상한, 목적함수 계수, 형, 이름)입니다. 3장의 gurobipy 예와 같은 호출이고, 세 겹 for 루프가 "∀ p < q, ∀ i"입니다. 목적함수 계수는 여기서 0으로 두고 뒤에서 한꺼번에 줍니다. 이름 문자열은 디버깅용이고 줄여 적은 곳은 ...로 표시했습니다. 배열은 모든 첨자 조합만큼 넉넉하게 잡혀 있어서 p ≥ q처럼 쓰이지 않는 자리는 빈 채로 남습니다. 뒤의 코드에서 식을 쌓는 데 쓰는 GRBLinExpr은 "변수들의 1차식"을 담는 Gurobi의 자료형이고, model.addConstr(식 ≤ 식, 이름)이 제약 하나를 모형에 등록합니다.

2부 · 목적함수와 제약식

목적함수: 구간 하나에 경로 둘

최소화  Σp<q Σi=1..N−1 2 · (F + dist(i)) · xpqi

구간 하나는 선적 경로 하나와 하역 경로 하나를 만듭니다. 각각의 비용이 F + (길이)이고 길이를 dist(i)로 잡으면 구간 하나의 비용은 2(F + dist(i))입니다. 이것을 모든 구간에 대해 더한 것이 총비용입니다. 3장의 "이진변수에 숫자를 곱해 더하면 고른 것들의 합" 패턴입니다.

// function.cpp 164~176줄
objective += x_pqi[idx3(p, q, i, num_ports, num_nodes)] * (2 * (nodeVec[i]._dist + fixed_cost));
...
model.setObjective(objective, GRB_MINIMIZE);
  • 임시 하역의 비용이 자동으로 들어갑니다. 구간을 둘로 쪼개면 x가 하나 더 켜지고 2(F + dist)가 한 번 더 붙습니다. 재배치 경로 두 개의 비용입니다. z에는 비용 계수가 없습니다.
  • LB는 빼지 않습니다. 상수라서 최소화에 영향이 없습니다.
  • 모든 계수가 짝수입니다. 따라서 목적함수 값은 언제나 짝수입니다. 8장에서 쓰입니다.
  • 길이는 "차가 없는 배에서의 최단 거리"로 계산합니다. 머무는 차 때문에 돌아가야 해서 실제 경로가 더 길어지는 경우는 반영되지 않습니다. 이 점은 4부에서 따집니다.

제약 ① 수요: 구간의 개수 맞추기

"p에서 실어 q에서 내리는 구간"이 몇 개 있어야 하는지를 정하는 식입니다. 임시 하역이 없다면 간단합니다. Σi xpqi = dpq, 즉 수요만큼의 칸을 골라야 합니다. 임시 하역이 있으면 구간이 쪼개지면서 개수가 달라집니다.

Σi xpqi = dpq − Σp<r<q zprq + Σr>q zpqr + Σr<p zrpq∀ p < q

3장의 수량 보존 꼴입니다. (p, q) 구간의 개수는 원래 수요에서, 쪼개져 없어진 만큼 빼고, 다른 구간이 쪼개지면서 생긴 만큼 더한 것입니다.

항뜻그림으로
dpq원래 수요p ━━━━━━━ q
− Σp<r<q zprq(p, q) 구간이 사이의 항구 r에서 쪼개져 없어진 수p ━━ r ━━ q   → (p,q)가 사라짐
+ Σr>q zpqr더 긴 (p, r) 구간이 q에서 쪼개지며 앞 토막으로 생긴 수p ━━ q ━━ r   → 앞 토막이 (p,q)
+ Σr<p zrpq더 긴 (r, q) 구간이 p에서 쪼개지며 뒤 토막으로 생긴 수r ━━ p ━━ q   → 뒤 토막이 (p,q)

쪼개져 생긴 토막이 다시 쪼개질 수도 있습니다. 식은 "원래 수요인지 토막인지"를 구별하지 않고 (p, q) 구간을 한 주머니에 넣어 세기 때문에, 한 차를 두 번 세 번 임시로 내리는 것도 저절로 표현됩니다.

// function.cpp 80~94줄. 식의 항을 모두 왼쪽으로 옮긴 모양
for (PortId p = 0; p < num_ports - 1; ++p)
    for (PortId q = p+1; q < num_ports; ++q)                       // ∀ p < q
    {
        GRBLinExpr lhs = 0.0;
        for (NodeId i = 1; i < num_nodes; ++i)
            lhs += x_pqi[idx3(p, q, i, num_ports, num_nodes)];      // Σ_i x_pqi
        for (PortId r = p+1; r < q; ++r)         lhs += z_pqr[idx3(p, r, q, ...)];  // + 쪼개져 없어진 수
        for (PortId r = 0; r < p; ++r)           lhs -= z_pqr[idx3(r, p, q, ...)];  // − 뒤 토막 수
        for (PortId r = q+1; r < num_ports; ++r) lhs -= z_pqr[idx3(p, q, r, ...)];  // − 앞 토막 수
        model.addConstr(lhs == demandQuantityVec[idx2(p, q, num_ports)], "Demand_...");
    }

항구가 P개면 이 제약은 P(P−1)/2개입니다. 수요가 없는 쌍(dpq = 0)에도 식이 있습니다. 토막으로 생긴 구간은 원래 수요가 없는 쌍에도 생길 수 있기 때문입니다.

제약 ② 머무는 차가 있는 칸은 접근 불가

Σp<q Σr>q xpri ≤ 1 − yqi∀ q = 1..P−2, ∀ i = 1..N−1

왼쪽은 "q보다 전에 실려 q보다 뒤에 내려지는, 칸 i의 구간"을 모두 더한 것입니다. 즉 항구 q에서 칸 i에 머무는 차의 수입니다. 3장의 x1 + x2 + … ≤ 1 − y 꼴이고, 두 가지를 한 번에 말합니다.

  • 머무는 차는 많아야 한 대다(오른쪽이 최대 1이므로).
  • 머무는 차가 있으면 yqi = 0, 즉 그 칸은 항구 q에서 접근 불가다. 5장 규칙 (나)입니다.
// function.cpp 146~161줄
for (PortId q = 1; q < num_ports - 1; ++q)
    for (NodeId i = 1; i < num_nodes; ++i)
    {
        GRBLinExpr expr = 0.0;
        for (PortId p = 0; p < q; ++p)
            for (PortId r = q + 1; r < num_ports; ++r)
                expr += x_pqi[idx3(p, r, i, num_ports, num_nodes)];
        model.addConstr(expr <= 1 - y_pi[idx2(q, i, num_nodes)], "Occupied_Node_Inaccessibility_...");
    }

제약 ③④ 내리거나 실으려면 접근 가능해야

③Σp<q xpqi ≤ yqi∀ q = 1..P−2, ∀ i = 1..N−1
④Σq>p xpqi ≤ ypi∀ p = 1..P−2, ∀ i = 1..N−1

③의 왼쪽은 항구 q에서 칸 i로부터 내리는 구간의 수, ④의 왼쪽은 항구 p에서 칸 i에 싣는 구간의 수입니다. 3장의 x1 + x2 + … ≤ y 꼴이고, 역시 두 가지를 말합니다.

  • 한 항구에서 한 칸으로부터 내리는 차는 많아야 한 대, 싣는 차도 많아야 한 대다.
  • 내리거나 실으려면 그 칸이 그 항구에서 접근 가능해야 한다.

③과 ④는 서로를 막지 않습니다. 같은 항구에서 같은 칸에 대해 ③의 x와 ④의 x가 둘 다 1일 수 있습니다. 차를 내리고 그 자리에 다른 차를 싣는 것이고, "내린 다음 싣는다"는 순서 덕분에 가능합니다.

// ③ 하역 쪽 (function.cpp 118~130줄)
for (PortId q = 1; q < num_ports - 1; ++q)                 // ∀ q = 1..P−2
    for (NodeId i = 1; i < num_nodes; ++i)                 // ∀ i = 1..N−1
    {
        GRBLinExpr expr = 0.0;
        for (PortId p = 0; p < q; ++p)
            expr += x_pqi[idx3(p, q, i, num_ports, num_nodes)];      // q에서 끝나는 구간
        model.addConstr(expr <= y_pi[idx2(q, i, num_nodes)], "Unloading_Accessibility_...");
    }

// ④ 선적 쪽 (132~144줄)
for (PortId p = 1; p < num_ports - 1; ++p)                 // ∀ p = 1..P−2
    for (NodeId i = 1; i < num_nodes; ++i)
    {
        GRBLinExpr expr = 0.0;
        for (PortId q = p + 1; q < num_ports; ++q)
            expr += x_pqi[idx3(p, q, i, num_ports, num_nodes)];      // p에서 시작하는 구간
        model.addConstr(expr <= y_pi[idx2(p, i, num_nodes)], "Loading_Accessibility_...");
    }

제약 ⑤⑥ 접근 가능성의 전파

⑤ypi ≤ Σj ∈ pred(i) ypj∀ p = 1..P−2, ∀ i = 1..N−1
⑥yp0 = 1∀ p = 1..P−2

⑤는 3장의 "y이면 x1, x2, … 중 적어도 하나" 꼴입니다. 칸 i가 접근 가능하려면 아래 이웃 중 하나는 접근 가능해야 한다는 5장 규칙 (다)입니다. ⑥은 출입구는 항상 접근 가능하다는 규칙 (가)입니다.

// function.cpp 96~116줄
for (NodeId i = 1; i < num_nodes; ++i)
{
    vector<NodeId> predVec;                                    // pred(i)를 만든다
    for (NodeId neighbor : nodeVec[i]._neighborVec)
        if (nodeVec[neighbor]._position < nodeVec[i]._position)
            predVec.push_back(neighbor);
    for (PortId p = 1; p < num_ports - 1; ++p)
    {
        GRBLinExpr expr = 0.0;
        for (NodeId j : predVec) expr += y_pi[idx2(p, j, num_nodes)];
        model.addConstr(expr >= y_pi[idx2(p, i, num_nodes)]);
    }
}

이 여섯 가지가 제약식의 전부입니다. 경로도 순서도 등장하지 않습니다. big-M도 없습니다. 모든 계수가 0, 1, −1입니다.

한 칸에 두 대가 겹치는 일은 왜 없는가

"한 칸에는 언제나 한 대 이하"를 직접 말하는 식은 없습니다. ②③④가 함께 그 일을 합니다. 칸 i에 구간 A(p₁에서 q₁)와 구간 B(p₂에서 q₂)가 겹쳐 있다고 가정하고 모순을 찾습니다. 두 구간 중 먼저 시작하는 쪽을 A라고 부르고(p₁ ≤ p₂), 동시에 시작하면 먼저 끝나는 쪽을 A라고 부르기로 하면, 겹치는 방식은 두 가지뿐입니다.

  • B가 A의 도중에 시작하는 경우 (p₁ < p₂ < q₁). 항구 p₂에서 A는 머무는 차입니다. ②에 의해 y = 0. 그런데 B를 p₂에서 실어야 하니 ④에 의해 y = 1. 모순입니다.
  • 같은 항구에서 시작하고 A가 먼저 끝나는 경우 (p₁ = p₂, q₁ < q₂). 항구 q₁에서 A를 내려야 하니 ③에 의해 y = 1. 그런데 B는 머무는 차이니 ②에 의해 y = 0. 모순입니다.

두 경우 모두 모순이 생기는 항구(p₂ 또는 q₁)는 첫 항구도 마지막 항구도 아닙니다. 그래서 y가 없는 항구 0과 P−1에 대해 따로 식을 두지 않아도 됩니다. 시작과 끝이 모두 같은 두 구간은 같은 변수 xpqi이므로 애초에 두 개가 될 수 없습니다.

아래 숫자는 팀의 코드나 Gurobi를 실행해서 얻은 것이 아닙니다. 이 문서를 쓰면서 같은 모형을 순수 Python으로 옮겨 작은 문제를 전수 탐색하는 프로그램(10장 부록에 전체 코드)을 만들어 계산했습니다. 이 프로그램은 차마다 "여정을 어느 항구들에서 쪼갤지"의 모든 경우를 만들고, 그렇게 생긴 구간들을 칸에 배정하는 모든 경우를 훑으면서 제약 ②~⑥을 지키는 것 중 가장 싼 것을 찾습니다. 경우를 빠짐없이 보므로 찾은 값 190은 이 모형의 최적값입니다(프로그램에 오류가 없다는 전제에서). 얻은 해는 7장의 복원 절차를 거쳐 채점 규칙으로 검사했고 유효했습니다. 최적해가 여러 개일 수 있으므로 Gurobi는 값은 같고 배치가 다른 해를 낼 수 있습니다.

이 해가 하는 일을 말로 풀면 이렇습니다. 수요 0의 두 대(항구 0 → 2)를 항구 0에서 바깥쪽 칸 1, 2에 싣습니다. 항구 1에서 이 두 대를 임시로 내리고, 오래 탈 수요 1(→ 항구 4)과 수요 3(→ 항구 3)을 안쪽 칸 4, 3에 먼저 넣은 뒤, 수요 0의 두 대를 다시 칸 2, 1에 싣습니다. 그러면 이후로는 항상 바깥쪽 차가 먼저 내리게 되어 재배치가 더 필요 없습니다.

공식 예시 해도 재배치는 두 대였습니다(항구 2에서 수요 1과 3). 대수는 같은데 비용이 다른 이유는 어느 칸을 썼느냐입니다.

칸 1 (구간당 22)칸 2 (24)칸 3 (26)칸 4 (28)합
공식 예시 해구간 3개2개2개1개66 + 48 + 52 + 28 = 194
모형의 최적해구간 4개2개1개1개88 + 48 + 26 + 28 = 190

구간당 비용은 2(F + dist(i)) = 2(10 + dist(i))입니다. 최적해는 안쪽 칸 3을 한 번 덜 쓰고 가장 싼 칸 1을 한 번 더 씁니다. 임시 하역 한 번은 구간을 하나 늘리므로, 새로 생긴 토막이 쓰는 칸 j에 대해 2(F + dist(j))가 목적함수에 더해집니다. 다만 쪼개면 다른 구간들이 더 가까운 칸을 쓸 수 있게 되기도 해서, 전체 비용이 정확히 그만큼 늘지는 않습니다. 두 해의 차이 4가 그런 효과입니다. 사람이 손으로 풀면 "일찍 내릴 차를 바깥에" 놓는 데까지만 생각하기 쉬운데, 솔버는 "어차피 두 대를 재배치해야 한다면 어느 항구에서 하는 것이 칸을 더 싸게 쓰는가"까지 따집니다.

반대로 공식 예시처럼 수요 0을 칸 3, 4에 싣고 항구 1에서 수요 1, 3을 칸 2, 1에 쪼개지 않은 채(x142 = x131 = 1) 싣는 배치를 넣어 보면, 항구 2에서 칸 3을 내리기 위해 y23 = 1 → y22 = 1이 필요한데 칸 2에는 머무는 차 x142가 있어 ②가 y22 = 0을 요구합니다. 불능입니다. 칸 1의 x131도 같은 이유로 걸립니다(y22 ≤ y21이어야 하는데 칸 1에도 머무는 차가 있습니다). 그래서 그 배치를 쓰려면 두 대를 모두 항구 2에서 쪼개야 합니다. x142 대신 x122와 x243을, x131 대신 x121과 x231을 쓰고 z124 = z123 = 1로 둡니다. 그것이 공식 예시 해이고, 이 모형의 가능해입니다(비용 194).

일렬 배에서는 재배치를 피할 수 없었습니다. 가지가 있으면 사정이 달라집니다. 1장 그림 (가)의 배(N = 8)에 항구 4개, F = 10, 수요 [[0,3],2], [[0,2],1], [[1,3],1], [[1,2],2], [[2,3],2]를 주고 같은 프로그램으로 풀면, 임시 하역 없이(z가 모두 0) 다음 배치가 나옵니다.

크기: x는 항구 수의 제곱으로 자란다

변수의 대부분은 x이고, x의 수는 (칸 수) × (항구 쌍의 수)입니다. 발표자료 6쪽의 표현으로는 결정변수가 O(노드 수 × 항구 수²), 제약식이 O(노드 수 × 항구 수)입니다. 노드가 두 배면 두 배지만 항구가 두 배면 네 배가 됩니다. 발표자료는 "항구의 수에 영향을 크게 받음"이라고 적고 있습니다. z는 항구 수의 세제곱에 비례하지만(P = 20일 때 1,140개) 노드 수와 무관해서 x에 비하면 적습니다.

강도: big-M이 없다

4장에서 본 잣대로 보면 이 모형은 좋은 편에 속합니다.

  • 논리 제약 ②③④는 여러 x를 한 줄에 모은 꼴입니다. 4장에서는 "한 줄에 모은 식이 약하다"고 했는데, 그것은 y 앞에 10이라는 큰 계수(big-M)가 붙어 x 열 개가 동시에 1이 될 수 있었기 때문입니다. 여기서는 y의 계수가 1입니다. 어차피 x들 중 하나만 1이 될 수 있다는 사실까지 식에 담은 것이라, "x 각각 ≤ y"로 풀어 적는 것보다 오히려 강합니다. 소수 해로 확인해 보면, x1 = x2 = 0.5, y = 0.5는 풀어 적은 식(0.5 ≤ 0.5)을 통과하지만 모은 식(0.5 + 0.5 ≤ 0.5)은 통과하지 못합니다.
  • big-M이 없습니다. 스위치가 반쯤 켜진 소수 해로 제약을 빠져나가는 길이 좁습니다.

약한 고리는 ⑤입니다. 아래 이웃이 둘이면 ypi ≤ ypj + ypk이고, LP에서는 두 이웃이 각각 0.5씩만 접근 가능해도 i가 완전히 접근 가능하다고 칠 수 있습니다. 격자처럼 순환이 많은 배에서 LP 완화가 얼마나 느슨해지는지는 실제 문제에 돌려 봐야 알 수 있고, 이 문서에서는 확인하지 못했습니다.

모형이 최적으로 풀려도 그것은 "모형의" 최적해입니다. 원래 문제와의 차이를 정리합니다.

앞의 두 가지는 5장에서 봤습니다. 세 번째는 여기서 처음 나옵니다. 제약 ⑤는 "아래 이웃 중 하나가 접근 가능"만 요구하는데, 아래 이웃에는 같은 거리에 있으면서 높이만 낮은 이웃도 포함됩니다. 그런 이웃을 거쳐 내려가면 길이가 dist(i)보다 길어집니다. 세 가지 길이의 크기 관계를 적어 두면 이렇습니다.

dist(i) ≤ 머무는 차를 피한 실제 최단 경로의 길이 ≤ 높이를 따라 내려가는 경로의 길이

모형이 비용 계산에 쓰는 것은 맨 왼쪽이고, 실제로 출력되어 채점되는 것은 가운데입니다(7장). 맨 오른쪽은 모형이 "길이 있다"고 판정할 때 근거로 삼는 길입니다.

노드 다섯 개가 고리로 이어진 배(0-1-2-3-4-0, 출입구와 칸 네 개)로 봅니다. BFS는 1, 4, 2, 3 순으로 방문하고, 노드 3의 거리는 2(3 → 4 → 0), 아래 이웃은 pred(3) = {2, 4}입니다. 노드 4에 머무는 차가 있으면 3은 2를 근거로 접근 가능하고, 실제로 나가는 길은 3 → 2 → 1 → 0, 길이 3입니다. 모형은 이 경로를 길이 2로 계산합니다.

이런 일이 생기려면 거리가 같은 두 노드가 이웃이어야 하고, 그것은 그래프에 홀수 길이의 순환이 있다는 뜻입니다. 거리가 둘 다 d인 이웃 i, j가 있으면 "출입구에서 i까지(d걸음), i에서 j로(1걸음), j에서 출입구까지(d걸음)"가 2d + 1걸음짜리 닫힌 길이 되기 때문입니다. 위 고리에서는 노드 2와 3이 그런 쌍이고 고리의 길이가 5입니다. 순환이 없는 배(트리)나 순환이 모두 짝수 길이인 배(대각선 없는 격자)에서는 이웃끼리 거리가 항상 1 차이 나므로, 아래 이웃은 모두 거리가 1 작고, 모형의 비용과 실제 비용이 정확히 일치합니다. 홀수 길이의 순환이 없는 그래프를 그래프 이론에서는 이분 그래프(bipartite graph)라고 부릅니다. 노드를 "거리가 짝수인 것"과 "홀수인 것" 두 편으로 나누면 모든 간선이 두 편 사이만 잇는 그래프입니다.

대회 사이트의 「문제 생성 방법」에는 격자에 삼각형 모양이나 대각선 간선을 넣는 옵션(tri, diag)이 있다고 적혀 있어서, 그런 문제에서는 차이가 날 수 있습니다. 다만 위에서 본 공개 연습 문제 20개는 직접 검사해 보니 모두 홀수 순환이 없었습니다. 이 20문제에서는 모형의 목적함수 값이 채점기가 계산할 총비용과 정확히 같습니다. 숨겨진 평가 문제도 그랬는지는 확인하지 못했습니다.

어느 경우든 제출된 해는 유효합니다. 차이는 "솔버가 최소화한 값"과 "채점기가 계산한 값"이 조금 다를 수 있다는 것뿐입니다. 실제 경로가 어떻게 만들어지는지는 7장에서 봅니다.

이해 확인

x243 = 1을 한국어 문장으로 읽어 보세요.

"항구 2에서 칸 3에 실려 항구 4에서 내려지는 구간이 있다." 항구 2를 떠날 때부터 항구 4에 닿을 때까지 칸 3에 차가 있습니다. 항구 3에서 이 차는 머무는 차입니다.

항구가 5개일 때 제약 ②에서 q = 2, 칸 i에 대한 식의 왼쪽을 풀어 써 보세요.

p는 0, 1이고 r은 3, 4이므로 x03i + x04i + x13i + x14i입니다. 항구 2를 사이에 끼고 있는 구간 네 가지입니다.

z124 = 1이면 제약 ①의 어느 식들이 영향을 받나요?

세 식입니다. (1, 4)의 구간 수가 1 줄고, (1, 2)의 구간 수가 1 늘고(앞 토막), (2, 4)의 구간 수가 1 늡니다(뒤 토막).

임시 하역 한 번이 목적함수에 더하는 비용은 얼마인가요?

구간이 하나 늘어나므로 x가 하나 더 켜집니다. 새로 생긴 토막이 쓰는 칸을 j라 하면 2(F + dist(j))가 더해집니다. 다만 쪼개면서 칸을 바꾸면 다른 구간의 칸 배정도 달라질 수 있어, 전체 비용 변화는 그보다 작을 수도 클 수도 있습니다.

ypi = 1인데 칸 i에서 아무것도 싣지도 내리지도 않는 해는 허용되나요?

허용됩니다. y는 목적함수에 없고, 제약은 "쓰려면 1이어야 한다"와 "1이려면 아래 이웃이 받쳐 줘야 하고 머무는 차가 없어야 한다"만 요구합니다.

제약 ⑤에서 pred(i) 대신 모든 이웃을 쓰면 어떤 해가 잘못 허용되나요?

출입구와 끊긴 칸들이 서로를 근거로 접근 가능하다고 주장하는 해입니다(5장의 고리 그림 (가)). 솔버는 그 칸들에 차를 싣고 내리는 해를 낼 것이고, 실제로는 길이 없으므로 무효해가 됩니다.
